# 보석 획득·스테이지 클리어 에셋 적용

## 구성과 디자인

기존 큰 모자·짧은 몸통·검은 얼굴과 안광·붉은 머플러 주인공의 획득 동작 확장이다. 보석과 후광, 링, 섬광은 개별 PNG로 제공한다. 빛 효과끼리는 같은 이미지에 들어 있지 않으므로 다른 효과까지 잘리는 문제가 없다. 캐릭터는 별도 8포즈 시트와 실측 추출 좌표를 사용한다. 원본 PNG는 보존하며 그림을 다시 그리거나 보간하지 않았다. 캐릭터 추출 사각형 사이 여백은 최소 가로 107px, 두 행 사이 165px다. 효과 PNG는 서로 다른 파일이므로 이웃 효과가 포함될 수 없다.

`assets/`의 PNG, `atlas.json`의 추출 좌표, 이 문서를 함께 사용한다. 좌표는 왼쪽 위 원점의 픽셀 단위이며 `rect=[x,y,width,height]`다. 자동 등분보다 명시된 좌표로 추출한다. 투명 여백이 있으므로 PNG 전체 폭을 캐릭터 몸체 폭으로 취급하지 않는다.

## 원래 명세와 달라지는 완료 조건

기존 출구 도달 조건을 **클리어 보석 접촉**으로 대체한다. 스테이지에 `clear_gem` 1개를 배치한다. 원래 선택 수집품은 별도 타입·ID로 관리하고 클리어 보석과 혼동하지 않는다. 최종 목표는 안전하고 넓은 곳에 배치한다. 공중 획득도 허용하되 아래 규칙대로 접촉 위치에서 정지시킨다.

같은 물리 틱에 위험물 접촉과 보석 접촉이 함께 발생하면 원래 명세의 우선순위를 유지하여 사망을 먼저 처리한다. 플레이어의 정상 신체 충돌체로 접촉을 검사한다. 후광·모자·머플러를 획득 판정으로 쓰지 않는다. 빠르게 지나갈 때 놓치지 않도록 스윕 센서 판정 또는 연속 충돌 검사를 사용한다.

## 상태 전환

`PLAYING → COLLECTING → CLEARED`의 단방향 전환으로 처리한다.

1. 유효 접촉이 확인되면 `PLAYING` 상태인지 검사하고 획득을 한 번만 확정한다.
2. 그 순간 스테이지 기록 시간을 확정한다. 획득 연출 시간은 클리어 기록에 더하지 않는다.
3. `COLLECTING`으로 바꾸고 캐릭터 월드 위치·바라보는 방향을 고정한다. 선속도·각속도·외부 충격량을 0으로 만든다.
4. 이동·점프·사격·갈고리·R 재시작 입력과 입력 버퍼를 비운다. 갈고리 제약과 줄·발사체, 총 조준 레이어를 해제한다. 입력을 누른 채 진입해도 종료 후 추가 사격이 발생하지 않게 한다.
5. 플레이어 물리 이동·중력·움직이는 발판의 속도 전달·기류를 정지한다. 함정과 이동 장치의 시뮬레이션도 정지하고 획득 뒤 사망 판정을 받지 않는다. 공중에서는 낙하하거나 안전 발판으로 순간이동하지 않고 접촉 지점에 머문다.
6. 카메라 선행 이동을 멈춘다. 획득 애니메이션과 빛 효과는 별도 연출 시계로 계속 갱신한다. 물리 시간을 0으로 설정한 뒤 같은 delta로 연출까지 정지시키지 않는다.
7. 아래 약 1초의 비반복 연출을 재생한 뒤 `CLEARED`로 전환한다. 진행 해금과 결과 저장은 중복 호출 없이 한 번 실행한다. 결과 화면에서 다음 스테이지·재도전을 제공한다.

일시정지·앱 비활성 때는 연출 시계도 멈춘다. 획득 연출 도중 종료한 경우 재실행 시 진행이 유실되지 않도록 획득 확정 시 완료 기록을 먼저 원자적으로 저장하고, 결과 화면은 연출 후 표시하는 구현을 권장한다. 이때 COLLECTING을 재개해야 하는지 결과 화면으로 복귀할지 저장 정책을 하나로 정한다.

## 8포즈 재생 예시

| 프레임 | 시간 | 동작·보석 처리 |
|---|---:|---|
| 0 | 0–100ms | 정지 진입. 기존 월드 보석을 잠시 유지 |
| 1 | 100–200ms | 손을 준비하며 보석을 손 근처로 이동 시작 |
| 2 | 200–300ms | 손을 뻗어 받기. 월드 보석을 숨기고 연출용 보석만 표시 |
| 3 | 300–420ms | 가슴 근처로 모으기 |
| 4 | 420–540ms | 모자 옆으로 들어 올리기 |
| 5 | 540–720ms | 모자 높이로 든 포즈 유지. 작은 섬광과 확산 링 1회 |
| 6 | 720–840ms | 손을 낮추며 보석·후광을 서서히 숨기기 |
| 7 | 840–1000ms | 마무리 자세. 마지막 프레임 유지 후 결과 표시 |

이 시간은 권장 시작값이다. 프레임 보간으로 픽셀 그림을 늘이거나 녹이지 않는다. 엔진에서 실제 재생을 보고 시간을 조절한다. 몸체 이동은 0이지만 손·머플러·옷의 애니메이션은 계속 움직인다.

## 프레임 정렬과 보석 장착

각 포즈는 그림 영역을 자른 크기가 다르다. 잘린 이미지의 왼쪽 위를 같은 좌표에 붙이면 캐릭터가 흔들린다. 고정 캔버스에 배치하거나 프레임별 발 기준점(pivot)을 사용한다. atlas.json에 프레임별 발 기준점 `pivot_px`와 손 소켓 `gem_socket_px`의 초기 좌표를 포함했다. 두 값 모두 잘린 rect 내부의 픽셀 좌표다. 육안으로 지정한 초기값이며 실제 엔진에서 검증한 확정값은 아니다. 기존 주인공의 기준점과 맞추고 실제 렌더링으로 확인한다.

보석은 캐릭터에 직접 합성되지 않았다. `gem_socket`을 프레임별 손바닥 위에 지정하고 같은 보석 PNG를 그린다. 좌우 반전 시 몸체와 소켓의 x좌표도 함께 반전한다. 원본 정수 픽셀 좌표계에서 위치를 지정하고 카메라 변환은 한 번만 적용한다. 손 소켓으로 이동할 때는 100–300ms 구간에만 짧게 보간한다. 이후 프레임별 손 위치를 따른다.

기존 주인공과 동일한 머리·부츠 크기가 되도록 전체 획득 시트에 동일 배율을 적용한다. 매 프레임을 제각각 같은 높이로 강제 확대하면 팔을 드는 프레임에서 몸체가 작아지므로 금지한다.

## 보석·빛 레이어

아래부터 후광 → 캐릭터 → 보석 → 섬광·확산 링 → HUD 순서로 그린다. 보석을 손 뒤에 숨겨야 하는 경우에만 손 앞 레이어를 추가한다.

- 월드 보석: 신체 높이의 약 0.35–0.45배, 상하 흔들림은 높이의 0.02배 이내, 주기 약 1.6초부터 시작한다.
- 후광: 보석을 중심으로 배치하고 평상시 알파 0.12–0.25, 획득 시 최대 약 0.4로 제한한다.
- 링: 프레임 5 시작에 0.65배에서 1.8배까지 약 240ms 확대하며 알파를 0.4에서 0으로 줄인다.
- 섬광: 프레임 5 시작에 약 100–160ms만 표시한다. 화면 전체 플래시는 사용하지 않는다.
- 빛 효과 PNG에는 투명 여백이 있다. 배율은 캔버스 크기만 보지 말고 실제 빛의 지름을 기준으로 정한다.
- 기본은 straight-alpha 블렌딩이다. additive를 선택하면 검은 배경을 제거하는 용도로 쓰지 말고 알파를 먼저 낮춰 과노출을 방지한다. 엔진의 premultiplied-alpha 설정과 텍스처 설정을 일치시킨다.
- 캐릭터·보석은 Nearest 필터와 정수 배율, 부드러운 후광·섬광은 Linear 필터를 권장한다. 한 아틀라스에 섞어 필터를 강제하지 않는다.

## 자르기·여백

빛 효과는 개별 파일 그대로 불러온다. 후광을 강하게 보이게 하려고 알파 경계를 임의로 잘라내면 사각형이나 원형 경계가 드러날 수 있다. 검은색 컬러키를 쓰면 주인공 얼굴과 윤곽도 사라지므로 금지한다. 캐릭터의 실측 rect는 이웃 포즈를 포함하지 않도록 분리한다. 별도 아틀라스에 재패킹할 때는 투명 패딩 16px 이상, 텍스처 가장자리 extrude 2–4px, 기본 mipmap off를 권장한다.

## 적용 확인

- 달리기·공중 스윙·낙하·사격 중 획득해도 캐릭터 월드 위치가 변하지 않는지 확인한다.
- 같은 틱의 위험 접촉은 사망으로 처리되고 클리어가 중복 확정되지 않는지 확인한다.
- 좌우 방향에서 발 위치·손 보석 위치가 튀지 않는지 확인한다.
- 30/60/144 FPS에서 연출 순서와 총 재생 시간이 같은지 확인한다.
- 일시정지·앱 비활성·재실행·다음 스테이지에서 입력과 물리 정지가 남지 않는지 확인한다.
- 각 프레임을 독립적으로 표시하여 옆 포즈·흐릿한 후광이 섞이지 않는지 확인한다.

이 문서는 엔진 독립 적용 가이드다. 실제 게임 코드에 연결하거나 플레이테스트한 결과를 포함하지 않는다. 이미지의 투명도·추출 좌표 검증 결과는 validation.json에 기록한다.
