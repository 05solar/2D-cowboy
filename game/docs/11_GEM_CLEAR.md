# 클리어 보석과 획득 연출

기준일: 2026-11-09. 프롤로그와 본편의 기존 출구 도달 완료를 바닥 `clear_gem` 접촉으로 대체했다. 원본 획득 가이드 [APPLY.md](../assets/gem_pickup/APPLY.md)는 자산/좌표 참고로 보존하며, 공중 획득 금지와 현재 HUD 요구는 이 문서를 따른다.

## 판정과 상태 전이

1. `PLAYING` 중 정상 플레이어 충돌체로 보석 접촉을 연속 검사한다. 모자·머플러·후광은 판정 범위에 포함하지 않는다.
2. 접지된 실제 바닥 위치에서 접촉해야 획득한다. 공중에서 닿아도 획득을 예약하지 않는다. 지상 스윕으로 고속 이동 중 보석을 놓치지 않게 한다.
3. 같은 물리 틱의 치명 위험·낙사와 보석 접촉은 사망을 먼저 처리한다.
4. 유효 접촉에서 `PLAYING → COLLECTING`을 한 번만 수행한다. 이 순간 위치·방향·기록 시간을 고정하고 속도·갈고리·발사 상태와 입력을 비운다.
5. 물리·이동체·함정·기류를 멈춘다. 플레이어는 공중 획득하지 않으며, 지상 접촉 위치에 고정된다. 별도 연출 시계는 약 2초 동안 동작한다.
6. 연출 종료 시 `CLEARED`로 바뀌고 다음 진행 해금/결과를 중복 없이 확정한다. HUD와 결과 제목은 `CLEAR`만 표시한다. 체크포인트 팝업 및 보석 설명 문구는 표시하지 않는다.

일시정지·앱 비활성 때 연출 시계도 정지한다. R·이동·점프·사격·갈고리 입력은 획득 중 소비한다. 보석 접촉 시간만 기록에 포함하고 연출 시간은 기록에 더하지 않는다.

## 애니메이션과 이미지

- 기존 주인공과 `gem_pickup_set_v1`의 8포즈/명시 atlas 좌표를 재사용한다. 원본 PNG와 atlas rect는 수정하거나 자동 등분하지 않는다.
- 현재 런타임 프레임 시간은 200/200/200/240/240/360/240/320ms, 총 2초다. 정수 픽셀 그림에 프레임 보간을 적용하지 않는다.
- 잘린 포즈의 발 pivot을 기준으로 몸체를 정렬하고, 손 소켓 좌표에 보석을 부착한다. 좌우 반전 시 pivot/socket x좌표도 반전한다.
- 월드 보석 표시 크기는 `clearGemVisualScale=2.0`이며 접촉 센서는 별도 데이터라 렌더 크기에 따라 커지지 않는다. 선택 보석은 별도 시각/ID다.
- 후광→캐릭터→보석→링/섬광→HUD 순서로 그린다. 빛 효과는 독립 PNG를 원본 전체 크롭 없이 사용한다. 캐릭터·보석은 nearest, 빛은 별도 부드러운 필터다.

## 저장

`ProgressStore`는 schemaVersion 2로 고정 stage ID별 완료·기록·수집품을 저장한다. 획득 시 `pending` journal을 먼저 기록한다. 연출이 끝나면 한 번 완료 처리하고 journal을 비운다. 재실행 시 남은 journal을 완료 처리한 뒤 결과 상태로 복원한다. 저장은 임시 파일 검증과 원자 교체를 사용하며, 더 높은 schema나 읽을 수 없는 원본을 임의 덮어쓰지 않는다.

과거 프롤로그 전용 `CompletionStore` 파일은 새 진행 파일이 없을 때만 가져오기 호환에 사용한다. 현재 공통 진행 저장 경로와 schema는 [05_DATA_AND_SAVE_SPEC.md](05_DATA_AND_SAVE_SPEC.md)가 기준이다. 임의 위치에서 이어하기 및 모든 손상 파일 시나리오가 제품 수준으로 검증된 것은 아니다.

## 검증 기록

2026-11-09 기준 cave core 회귀는 79 assertions 통과했고, 프롤로그 회귀는 과거 별도 실행 기록을 보유한다. 본 문서 정리 시 프롤로그 검증은 다시 실행하지 않았다. cave native 사망 화면 assertion 실패 이력은 [검증 상태](07_TEST_PLAN.md)에 기록하며 성공으로 간주하지 않는다. 30/60/144 FPS 전체 획득 효과, 일시정지·포커스 상실·재실행의 수동 UI 확인은 목적별로 추가 검증해야 한다.
