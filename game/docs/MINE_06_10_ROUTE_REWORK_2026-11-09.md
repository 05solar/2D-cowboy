# 광산 6~10: 실제 경로 위 장애물과 발판 재배치

2026-11-09 최신 수정. 이전의 장애물 수 합산만으로 난도를 검증했다는 설명은 불충분했다. 보석보다 위에 고립된 장치와 마지막 접근 구간의 장벽을 위로 피하던 생성 규칙을 제거했다.

추가 교정: 점프 궤적과 겹치는 것만으로는 보행 장애물을 보장하지 못했다. 지금 장벽 20개는 모두 발판 몸체 아래에서 시작해 보행면을 관통한다. 압착기는 최대 전개 시 발판에 닿고 톱은 보행 신체 높이에서 움직인다. 장벽을 넘겨 착지한 뒤 기다릴 수 있도록 발판 진입 쪽과 안전 대기 쪽을 구분했다. 압착기 그림도 이동량을 제한하던 표시 코드를 제거하고 실제 압착 길이와 끝 위치를 표시한다.

## 현재 배치

|---|---|---|---|

| 7 | 광차 뒤에 좌우로 돌아오는 S 경로와 수평 연결 | 3 / 0 / 0 / 2 | 11.008초, 4발 |
| 8 | 낮고 긴 횡단로, 작은 하강, 압착기를 통과하는 분리 발판 | 4 / 2 / 0 / 0 | 14.133초, 8발 |

발사 수는 전체 합계이며 정상 착지 후 재충전한다. 동시 탄약은 기존 2발이다. 마지막 넓은 발판에 보석을 두고 그 뒤에 위험물은 두지 않는다. 8~10의 중간 천장 링은 실제 갈고리 범위 내에 제공한다. 이번 자동 경로는 점프와 반동을 사용하며 갈고리 필수 경로를 증명하지 않는다.

## 데이터와 재생

- `tools/BuildMineStages.py`: 발판·이동체·CP·보석·천장 링 및 경로 데이터 생성.
- `assets/stages/mine_obstacles.json`: 스테이지 ID별 장치 좌표·주기·위상. 게임은 생성된 개별 스테이지 JSON을 읽는다.
- `assets/stages/mine_routes.json`: 실제 입력 드라이버의 발판 목표 순서. 장거리 구간은 발판 끝으로 걸어간 뒤 도약하고 유효 착지 충전을 기다린다.
- `MineRouteExposure.java`: 신체가 모든 장벽 영역·압착기 최대 압착 범위를 통과하는지 검사한다. 바닥 톱은 위험 반경 접근 또는 톱 위 도약 통과를 인정한다. 가시는 직접 닿으면 사망하므로 0.7H 이내 근접을 검사한다.
- `MineGroundHazards.java`: 장벽 20개의 발판 몸체 관통을 검사한다. 개별 장벽과 실제 지형을 격리 런타임에 읽어 활성/비활성 상태에서 바닥 보행 입력을 공급해 사망/통과를 각각 확인한다. 압착기와 톱의 보행 높이 도달도 검사한다.
- `build/mine-route-traces/*.csv`: 30FPS 표시 스케줄에서 고정 120Hz로 기록한 시간·위치·경로 단계. 검증 중 생성하며 런타임 맵 생성에는 필요하지 않다.

장애물 위치는 입력 궤적과 대조해 조정했고 톱·압착기는 고정 주기를 사용한다. 실행 중 플레이어 위치에 맞춰 장치나 위상을 바꾸지 않는다.

## 실행 결과

`.\gradlew.bat :core:verifyMines`: **284 assertions 통과**, 추가로 모든 경로의 장애물 범위 통과 검사 완료. 다섯 맵을 각각 30/60/144 FPS로 재생해 사망 없이 클리어했고 기록 시간과 획득 위치가 동일했다. 장치를 실제로 갱신하는 `StageRuntime`에 입력을 공급한 결과다.

총 9개 CP에서도 정지·2발로 출발해 클리어 가능한 입력을 찾았다. 8단계 CP1은 2.9초 관찰 대기를 둔 재생이 성공했다. 나머지는 추가 시작 대기 없이 성공했다. 드라이버는 장벽과 압착기의 개방 주기를 기다리고 바닥 톱 앞에서는 일찍 도약한다. CP 재생은 더 높은 발판에 착지하면 그 위치에서 이어가는 복구 조작을 허용한다. 이는 유일한 정답 시간이나 모든 출발 시각의 성공을 뜻하지 않는다.

`.\gradlew.bat :lwjgl3:verifyMinesNative`: **20 checks 통과**. 실제 창에서 다섯 카드·맵·배경과 활성 장벽을 로드했다. 화면 캡처만으로 클리어를 판정하지 않았다.

사람 대상 난도 순서·전체 지름길 탐색·갈고리 전용 경로 검증은 아직 하지 않았다. 자동 클리어 시간과 장애물 개수만으로 단계별 체감 난도를 보증하지 않는다.
