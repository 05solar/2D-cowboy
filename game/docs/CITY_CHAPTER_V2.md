# 지하도시 V2 적용 상태

## 2026-11-09 클리어 시간 단조성·장벽 주기 점검 결과 (시도했으나 되돌림)
`tools/BuildCityStages.py` 재생성 기준 clear 틱: city_01=7979, city_02=5349, city_03=10345, city_04=12101, city_05=12327(초 환산 66.49/44.58/86.21/100.84/102.73s). **city_02가 city_01보다 짧아 스테이지 순서와 클리어 시간이 단조 증가하지 않는다.** 아래 두 가지를 시도했으나 모두 되돌렸고, 현재 코드는 원래의 고정 4.2s off/1.2s on, 압착기 period=8.0 그대로다:
- city_02 모듈 뒤에 위험물 없는 안전 구간 플랫폼을 추가(광산 6/9번에 쓴 `extensions` 패턴과 동일한 의도): 8칸까지는 통과했지만 오히려 시간이 더 짧아졌고(4935틱), 16~20칸으로 늘리면 플랫폼 진입 지점에서 경로가 막혀 120000틱 타임아웃으로 실패했다. `CityRouteDriver`는 배열 인덱스 순서를 그대로 다음 목표로 쓰므로 모듈 뒤에 발판을 이어붙이는 접근 자체는 유효하지만, 정확한 지점에서 왜 막히는지는 끝까지 못 밝혔다.
- 스테이지별로 장벽 off/on 주기와 압착기 period를 차등화(광산에 쓴 패턴과 동일): city_03에서 압착기 접촉 사망이 재현됐다(`DEATH CAUSE city_03 mine=true`). 압착기 period만 원복해도 장벽 주기 차등만으로 같은 사망이 재현됐다 — 상류 장벽 대기 시간이 바뀌면 하류 압착기 도착 시각이 같이 밀려 안전창을 벗어나는 것으로 보인다(광산 9번에서도 같은 현상이 있었다).

두 시도 모두 `:core:verifyCity`가 원래 상태(340 assertions, 위 틱과 동일)로 되돌아간 것을 재확인했다. **현재 지하도시 챕터는 스테이지가 올라갈수록 전기장벽·압착기 주기가 짧아지지 않으며(전부 4.2/0.4/1.2, period 8.0 고정), 발판과 일직선인 수평 전기장벽도 없다(전부 세로형, width 0.14/height 3.0).** 이 두 항목과 city_02 단조성은 미해결로 남겼다. 반면 다음은 이번에 코드로 직접 확인했다: `CityRenderer.java`에는 경광등/warning 스프라이트 참조가 없다(경광등 없음 확인). `CityVerification.java`의 breakable-platform 검사(intact→warning→collapse→gone→respawn 복귀)와 moving-platform rider displacement 검사는 실제로 340 assertions 안에서 수행되고 있다(문서상 주장이 아니라 코드로 확인).

작성: 2026-10-30, 상태 정리: 2026-11-09. 이 문서는 V2 적용 범위와 당시 검증 결과를 보존하는 챕터 기록이다. 최근 `:lwjgl3:verifyCityNative` 29 checks는 2026-11-09 실행됐지만, 기존의 도시 전체 플레이 경로 결과를 갱신하지 않는다. 최신 프로젝트 상태는 [결정·현재 상태](09_DECISIONS_AND_STATUS.md)를 본다. 원본 V1 문서와 이미지는 보존하고 V1 도시 아트는 런타임에서 로드하지 않는다.

## 적용 내용

- [v2_atlas.json](../assets/city_chapter/v2_atlas.json)의 명시 rect로 V2 시트를 로드한다. V2 PNG와 설계 자료는 `assets/city_chapter/assets_v2/`, `docs/assets/city_chapter/v2/`에 보존한다.
- 각 도시 스테이지에 새 가로 배경과 기존 세로 배경을 비반복 원경으로 등록했다. `CityBackgroundSelector`는 카메라 구역 히스테리시스와 0.35초 크로스페이드를 적용한다. 16:9 화면비와 게임플레이 충돌은 변경하지 않는다.
- V2 맵은 6/7/8/9/10 모듈 데이터, 얇은 보행판, one-way/solid·ropeStops 구분, 열린 비충돌 프레임, 이동판, 링·바람·장벽·톱·압착기·붕괴판 데이터를 사용한다. 얇은 판은 충돌체 높이 H 기준 0.16H로 시작한다. 그림 비율을 유지하고 투명 픽셀로 콜라이더를 만들지 않는다.
- 생성기에는 실제 이동거리 목표 100/125/150/180/210H를 기록하지만 `lengthMeasured=false`다. 이 목표를 완성 맵의 실측값이나 난도 상승 검증으로 간주하지 않는다.
- 고정 ID `city_01`~`city_05`와 진행/보석/체크포인트 동작을 유지한다. 사용자의 테스트 요청에 따라 다섯 스테이지를 선택·실행 가능 상태로 둔다.

## 실행한 검증

- `:core:verifyCity`: 데이터·충돌·장치 assertion 295개 통과. 스크립트 입력 경로는 `city_01`~`city_04`에서 clear gem에 도달했다. `city_05`는 경로 중 이동 장치 충돌로 사망해 clear gem에 도달하지 못했다. 이 자동 경로는 수동 플레이테스트가 아니다.
- `:lwjgl3:verifyCityNative`: 24개 확인 통과. V2 atlas, 10개 배경 변형, 다섯 스테이지 로드, 16:9 오프닝 카메라 및 시간 정지를 확인했다. 전체 구간 플레이테스트는 수행하지 않았다.
- `:core:verifyPrologue`: 134 assertion 통과. `:core:verifyCaves`: 79 assertion 통과(30/60/144 FPS 경로 검사 포함).
- 생성된 JSON 10개를 UTF-8로 파싱했고 `git diff --check`를 실행했다.

## 남은 검증

- 실제 조작으로 `city_01`~`city_05` 전체 경로, 체크포인트 재시작, 장치와 줄의 상호작용을 플레이테스트해야 한다. 특히 `city_05`의 자동 경로가 이동 장치에 사망하는 원인을 실제 게임에서 확인하고 구간 또는 통과 타이밍을 조정해야 한다.
- 100/125/150/180/210H 목표와 핵심 연계 수는 아직 실측·플레이 검증하지 않았다. 11→15 난도 상승, 최대속도 관통, 배경 전환 이음새, 플랫폼 정렬도 실제 카메라에서 확인되지 않았다.
- V2 전극 PNG에는 아크가 포함되어 있어 비활성 상태에서 중립 영역만 그린다. 수납 가시의 모든 전환 상태와 크러셔 주기의 실제 애니메이션은 별도 플레이 확인이 필요하다.
# 2026-11-09 자동 경로 재생 보완

실제 `StageRuntime`에 입력을 넣는 도시 경로 재생에서 11~15가 clear_gem까지 도달하는 것을 확인했다. 15번의 톱은 경로 중심을 가로질러 기존 자동 경로를 사망시켜, 현재는 맵 가장자리의 별도 레일 구역으로 옮겼다. 13~15의 외곽 가시도 플레이 구간과 겹치지 않도록 좌표를 옮겼다.

생성기는 모든 층에 같은 좌표를 복제하던 배치를 4가지 좌우 실루엣과 4가지 높이 윤곽으로 교체했다. 이동 플랫폼·링·천장 앵커는 플랫폼 접촉면과 별도 데이터로 유지한다. 11~15 도시 5개 모두 120Hz 고정 틱 경로 재생에서 사망 없이 clear_gem에 도달했고, 30/60/144FPS의 이동체 주기 검사는 기존 검증에서 수행한다. 이는 스크립트 경로 재생과 장치 단위 검사이며 사람의 수동 플레이테스트 결과는 아니다.

도시 경로 길이·난도 순위의 실측은 아직 완료하지 않았다. 반복 구조 감소와 통과 가능성은 확인했지만, 11→15 난도 상승 및 이동 플랫폼·팬 표현을 실제 플레이 세션에서 추가 확인해야 한다.
