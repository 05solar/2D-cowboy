# 테스트 프롤로그 구현

작성일: 2026-10-26. 기존 기획과 사용자 제공 V3 에셋을 연결한 실제 실행 가능한 테스트 화면이다. 정식 20개 스테이지 전체의 완성본은 아니다.

2026-10-27 변경: 아래 초기 출구/영구 저장 미구현 설명 중 **클리어 조건과 완료 저장**은 [보석 획득 적용](11_GEM_CLEAR.md)으로 대체했다. 현재는 보석 접촉 → 정지 획득 연출 → 결과 표시이며 완료 기록은 획득 시 원자 저장한다. 체크포인트 일반 저장은 별도 후속 기능이다.

## 플레이 피드백 반영: 크기·총·스윙

- 캐릭터 표시와 충돌체를 기존의 75%로 축소했다. 현재 충돌체는 폭 0.345H, 높이 0.75H이며 H는 맵의 기존 기준 단위를 유지한다. 손·총·섬광·갈고리 연결점도 함께 맞췄다.
- 별도 회전 총 에셋은 불투명도 45%로 표시한다. 캐릭터 시트에 이미 그려진 총은 몸과 한 이미지이므로 원본대로 유지하며 캐릭터 전체를 반투명하게 만들지 않는다.
- A/D 스윙 가속은 접선 방향 20H/s², 입력 가속 상한은 12H/s다. 일반 공중 가속과 분리해 기존 4.5H/s 제한에 막히지 않는다. 전체 속도 상한 16H/s는 유지한다.
- 연결 후 줄을 최대 2.4H/s로 서서히 당겨 길이 3.7H까지 줄인다. 처음부터 더 짧은 줄을 늘리지는 않는다. 충돌 검사를 거쳐 위치를 보정한다.
- 해제 순간에는 축적된 속도를 그대로 유지한다. 반복 해제로 공짜 충격량이 생기지 않는다. 최신 사용자 피드백에 따른 변경으로, 원본의 연결 시 줄 길이 고정 규칙보다 이 프롤로그 조작안을 우선한다.
- 두 링을 연결하며 D로 가속하면 **총 발사 없이 건너편 x=36~41 발판에 착지 가능**하다. 반동은 추가 추진·보정에 사용할 수 있다. 5H의 천장 없는 구멍은 여전히 반동이 필요하다.

설정 위치: `assets/config/physics.json`의 `playerVisualScale`, `gunOpacity`, `swingAcceleration`, `swingSpeed`, `ropeRetractSpeed`, `swingRopeLength`.

## 실행

루트의 `run-prologue.bat`를 실행하거나 PowerShell에서 다음 명령을 사용한다.

```powershell
.\gradlew.bat lwjgl3:run
```

빌드: `gradlew.bat lwjgl3:jar`. 실행 JAR: `lwjgl3/build/libs/2D-CowBoy-1.0.0.jar`. 현재 환경에서 Java 21로 실행 확인한다. JRE 자체를 포함한 설치 패키지는 이번 범위에 없다.

## 조작

| 입력 | 기능 |
|---|---|
| A/D, 좌우 방향키 | 이동, 공중·스윙 보정 |
| Space | 기본 점프 |
| 마우스 | 조준 |
| 왼쪽 클릭 | 조준 반대 방향으로 반동, 클릭당 1발 |
| 오른쪽 버튼 유지 | 천장 링에 갈고리 발사·연결 유지 |
| 오른쪽 버튼 해제 | 줄 해제, 현재 속도 보존 |
| R | 마지막 활성 체크포인트에서 재시작 |
| Esc | 일시정지/재개 |
| F1 | 위치·속도·갈고리 상태 표시 |
| Enter 또는 R, 완주 후 | 처음부터 다시 시작 |

오른쪽으로 멀리 갈 때는 점프 후 **왼쪽 아래로 조준하고 발사**한다. 아래 방향 성분으로 체공 시간을 늘리고 왼쪽 방향 성분의 반동으로 오른쪽 속도를 더한다. 캐릭터 발사 포즈는 이때 원본 오른쪽 발사 시트의 좌우반전이다. 반대 진행에서는 조준 방향에 맞춰 대칭 처리한다.

## 실제 배치

| 과제 | 구멍 | 도구·의도 |
|---|---|---|
| 첫 발걸음 | x=8~10, 2H | 기본 점프로 통과 |
| 반동을 믿어라 | x=16~21, 5H | 천장·링 없음. 기본 점프로 불가, 점프+뒤/아래 한 발로 통과 |
| 천장에 길을 걸다 | x=27~36, 9H | 천장 x=27~36, y=7. 링 (29,6.6), (33.5,6.6). 스윙 가속→해제→재연결→관성 착지, 반동은 선택 보정 |
| 마지막 도약 | x=41~45, 4H | 천장·링 없음. 반동 점프 후 x=46.5 출구 |

체크포인트 x=12,23,38. 낙사 시 0.35초 대기 후 해당 지점으로 복원한다. 현재 체크포인트는 실행 중에만 유지한다. 로컬 영구 저장, 정식 메뉴, 수집품, 음향, 키 변경·토글 갈고리 등은 후속 작업이다.

사용자 최신 요구에 따라 **실제 천장 구조물에 부착된 링만** 갈고리 대상이다. 배경의 종유석, 일반 바닥·벽, 아무 공중 위치에는 연결되지 않는다. 링 사거리 7H, 발사 속도 40H/s, 적중 허용 반경 0.28H, 시야 차단을 검사한다. 반경은 조준 유효 표시와 실제 발사체 판정에 함께 적용하고 맵 로더가 천장 없는 링을 거부한다.

## 렌더링과 에셋 적용

- 원본 README와 atlas rect를 사용한다. 등분 추출·색상 키 제거·원본 이미지 편집 없음.
- 플레이어 프레임은 원본의 75% 크기로 2560×1440 논리 캔버스에 그린다. 발 접점 기준으로 정렬하고 캐릭터 충돌체는 별도 0.345×0.75H다.
- air는 수직 속도로 상승/정점/낙하 포즈를 선택한다. idle/run/swing은 시간 재생, recoil/death/land는 일회성 포즈다.
- 발사 시 뒤를 보는 좌우반전 포즈와 조준 방향으로 회전하는 총 부품, 발사 섬광을 사용한다. 원본 시트에 그려진 총과 추가 부품의 완벽한 레이어 분리는 아직 하지 않았다.
- 배경은 2배 정수 배율의 한 장으로 표시하고 제한된 패럴랙스만 적용한다. 반복하지 않는다.
- 모든 제공 텍스처는 Nearest, 플레이어·카메라는 논리 정수 좌표로 표시한다. 기본 창은 1280×720이며 논리 캔버스를 1/2로 표시한다. 창 리사이즈의 최종 배율, 타일 끝 조각·총·로프 길이는 게임 배치에 맞춘 비정수 크기를 허용한 프로토타입 예외다. 원본 파일을 리샘플링한 것은 아니다.
- UI는 한글 비트맵 글꼴과 독립 16:9 화면 좌표를 사용한다. 여백 클릭은 발사하지 않는다. 천장 하단이 HUD 밖에 보이도록 카메라 높이를 조정했다.

## 구현 파일

게임 소스는 `core/src/main/java/io/github/hookrecoil/` 아래 assets/input/physics/player/recoil/grapple/stage/rendering/ui/screens로 나눴다. `HookRecoilGame`이 조립하고 `StageRuntime`이 120Hz 시스템 순서를 관리한다. 플랫폼 런처는 기존 패키지에 유지해 패키징 경로 변경을 최소화했다. 모든 새 Java 파일에 상단 역할 주석이 있다.

현재 물리는 정적 사각형에 대한 축별 스윕과 최대 거리 줄 제약으로 구현했다. 이동 플랫폼·동적 강체·모서리 줄 감기는 이 프롤로그에 없다. 정식 물리 백엔드 결정 전체를 완료한 것으로 간주하지 않는다.

## 검증 명령과 자료

```powershell
.\gradlew.bat core:verifyPrologue
.\gradlew.bat build
```

검증 클래스는 `core/src/test/java/io/github/hookrecoil/PrologueVerification.java`. 실제 맵·물리 JSON과 게임 시스템을 사용하며 실패 시 빌드를 실패시킨다. `core:check`에 연결했다. 테스트 프레임워크 없이 명시적인 회귀 검증 프로그램으로 실행한다.

게임 화면 캡처 모드는 `-Dhookrecoil.screenshot=<절대 PNG 경로>`로 JAR을 실행하면 30프레임 렌더 뒤 캡처·정상 종료한다. `-Dhookrecoil.previewCheckpoint=1`은 캡처용 두 번째 체크포인트 시작이다. 일반 실행에는 적용되지 않는다.
