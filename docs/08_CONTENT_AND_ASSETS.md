# 콘텐츠와 에셋 연결 상태

기준일: 2026-11-09. 사용자 제공 PNG·atlas·설계 자료는 출처별 폴더에 보존한다. 런타임이 실제로 로드하는 리소스는 아래 표와 챕터 문서를 기준으로 확인한다. 원본 명세·에셋의 제작 당시 설계는 현재 코드보다 최신 상태를 뜻하지 않는다.

## 스테이지 범위

| 콘텐츠 | 실행 ID/데이터 | 리소스·적용 상태 | 검증 상태 |
|---|---|---|---|
| 프롤로그 | `prologue`, `assets/stages/prologue.json` | 튜토리얼 시트, 기존 플레이어, 보석 연출 사용 | 자동 회귀 기록 있음; 수동 밸런스 전수는 별도 |
| 동굴 | `cave_01`~`cave_05` | cave atlas·배경, 붕괴 발판; [동굴 상태](12_CAVE_CHAPTER.md) | core 경로 회귀 있음; 네이티브 사망 패널 실패 이력 재확인 필요 |
| 광산 | `mine_01`~`mine_05` | 광산 atlas·장치·배경; [광산 상태](MINE_CHAPTER_STATUS.md) | surface/native 로드 과거 통과; 자동 경로 실패 이력, 수동 클리어 미확인 |
| 지하도시 V2 | `city_01`~`city_05` | V2 얇은 판·열린 구조물·가로/세로 배경; [도시 상태](CITY_CHAPTER_V2.md) | 데이터/native 카메라 검증 있음; 전 경로 수동 미확인 |
| 지상 | `surface_01`~`surface_05` 카탈로그 메타데이터 | 게임 맵과 리소스 없음 | `available=false`, 실행 불가 |

프롤로그는 본편 20개 ID에 포함하지 않는다. 1~15의 `available=true`는 테스트 시작을 위한 설정이며 진행 해금이나 완주 증명이 아니다.

## 자산 적용 규칙

- atlas 실측 rect로 추출하고 PNG 투명도를 보존한다. 자동 등분 및 이미지 알파 기반 콜라이더 생성은 금지한다.
- 배경은 비반복 장식이다. 반복 타일 또는 충돌 지형으로 취급하지 않는다.
- 게임플레이 발판/위험/링/장치는 별도 데이터와 런타임 상태를 가진다. 장식 레이어가 충돌을 넓히지 않게 한다.
- 픽셀 아트는 nearest filtering을 사용한다. 원본 종횡비를 임의로 찌그러뜨리지 않는다.
- 동굴 붕괴 플랫폼은 3H/4H 너비를 단일 그림으로 늘이지 않고 최대 2H 단위 이미지 조각으로 나누어 표시한다.
- 미사용 사다리/가이드 레일은 기능이 없으면 런타임에서 제거한다. 실제 장애물·기능 장치는 사용하지 않아도 시각적 장애물일 경우 임의 삭제하지 않는다.

## 콘텐츠 생성·수정

| 대상 | 생성/기준 파일 |
|---|---|
| 본편 카탈로그 | `assets/cave_chapter/stages.json`, 고정 stage ID |
| 실제 스테이지 | `assets/stages/*.json` |
| 동굴 생성기 | `tools/BuildCaveMaps.py` |
| 광산 생성기 | `tools/BuildMineStages.py` |
| 도시 생성기 | `tools/BuildCityStages.py` |
| 공통 물리·카메라 | `assets/config/physics.json`, `camera.json` |
| 보석 획득 리소스 | `assets/gem_pickup/` 및 런타임 `GemAssets` |

생성기 산출물을 직접 고치면 재생성 시 덮어쓸 수 있다. 생성기와 JSON을 함께 확인한다. 지하도시의 100/125/150/180/210H 경로 목표 등은 설계 목표이며 실측된 완성 경로 길이가 아니다.

## 보존 자료

`docs/assets/`에는 에셋 도입 당시의 구현 프롬프트·레벨 청사진이 있다. 해당 문서의 과거 `available`, 카메라 크기, 경로/완료 조건은 현재 사양으로 읽지 않는다. 상태 문서가 우선하며 원문은 추적성을 위해 보존한다.
