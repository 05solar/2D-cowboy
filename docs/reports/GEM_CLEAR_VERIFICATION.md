# 보석 클리어 검증

## 최신 수정: 2초 포즈 연출

2026-10-28에 런타임 8프레임 체류 시간을 모두 두 배로 늘렸다. 현재 프레임 시간은 200/200/200/240/240/360/240/320ms, 합계 2초다. 원본 atlas와 PNG는 보존하며 gem 소켓 보간, 링, 섬광, 보석 소거 시간도 같은 비율로 이동했다. 진행 시간은 보석 접촉 때 고정해 연출이 더해지지 않는다.

회귀 테스트는 30/60/144FPS에서 2초 완료를 검사하고 프레임 5에서 링이 시작하는지 확인한다. 아래에 남은 당시 캡처 이미지는 최초 1초 타이밍을 적용했을 때 만든 시각 자료다. 현재 속도에 따른 포즈별 시각 검토 자료로 간주하지 않는다.

## 최신 수정: 바닥 획득만 허용

기존 회귀 131개 + 보석 회귀 85개, 총 216개 assertion 통과. 공중 이동·상승·낙하·갈고리 상태에서는 획득/저장하지 않으며, 낙하 후 실제 바닥 y=2에서 연출이 시작되는 것을 검증했다. 공중 접촉 후 다른 곳으로 이동한 경우 획득 예약이 남지 않는다. 지상 연출 고정·사망 우선·시간·저장/복구 검증도 유지한다.

아래 공중 획득 설명과 193개 검증은 최초 적용 당시의 이력이다. 최신 규칙은 바닥에서만 획득한다.

2026-10-27 / Windows 11 / Java 21 / libGDX 프롤로그.

## 자동 검증

기존 이동·반동·갈고리·충돌 회귀 131개와 보석 검증 62개를 실행한다. 보석 검증은 실제 런타임·저장 코드를 사용한다.

두 검증 모두 통과했으며 전체 `build`와 실행 JAR 생성도 성공했다. 총 193개 assertion이다.

- 정상 신체의 빠른 통과 감지, 후광 위치만 스치는 경우 미획득.
- 최초 접촉 위치 고정, 진행 방향 양쪽과 지상/상승/낙하/갈고리 및 발사 자세 진입 상태.
- 획득 후 속도·입력 버퍼·발사 자세·줄·갈고리 비행체 정리.
- 입력을 180틱 전달해도 획득 중 위치·방향·기록 시간 유지.
- 같은 틱 사망 우선, 획득 뒤 추가 위험 무시, 완료 저장 콜백 1회.
- 30/60/144FPS에서 2초의 별도 연출 시계, 마지막 포즈 및 프레임 5(1080ms) 링/섬광 시작.
- 제공 atlas의 프레임 시간 일치.
- 유지한 발사/R/Enter 차단, release 뒤 새 입력 허용.
- 연출이 끝나기 전에 실제 임시 디렉터리에 원자 완료 저장, 재실행 결과 복귀, 손상 본 파일의 정상 백업 복구.
- 재도전 시 물리/시도 시간 정상 재개.

## 렌더 검증

실제 데스크톱 실행으로 8포즈 × 좌우 방향, 총 16개의 독립 캡처를 생성했다. [오른쪽 획득 강조 포즈](gem-frames/pose-5-left-false.png), [왼쪽 획득 강조 포즈](gem-frames/pose-5-left-true.png).

발 접점, 손 위 보석, 좌우반전, 반투명 후광·링, 마지막 프레임에서 보석 소거를 시각 확인했다. 캐릭터/효과에 옆 포즈가 끼거나 빛의 외곽을 잘라낸 사각 경계가 보이지 않았다. 게임 화면 캡처는 실제 완료 저장과 분리했다.

앱 포커스/일시정지는 화면 코드의 연출 갱신 차단으로 처리한다. 장시간 실제 키보드/마우스 조작·모든 해상도·전원 차단 중 파일시스템 복구를 수동 검증했다고 주장하지 않는다. 다음 스테이지 콘텐츠가 없어 맵 간 전환 플레이테스트는 미실행이며 UI에 준비 중으로 표시한다.
