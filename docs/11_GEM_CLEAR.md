# 클리어 보석·획득 연출 적용

작성일: 2026-10-27. 사용자 제공 `gem_pickup_set_v1`의 [적용 원문](../assets/gem_pickup/APPLY.md)을 현재 프롤로그에 연결했다. 최신 사용자 요청으로 **공중 획득을 제외하고 바닥에서만 획득 연출을 시작**한다. 이 규칙은 원문의 공중 획득 허용보다 우선한다.

2026-10-28 갱신: 사용자 요청에 따라 프레임별 체류 시간을 두 배로 늘려 연출 전체를 2초로 재생한다. 제공 에셋의 원본 프레임 좌표와 1초 기준 시간은 보존하고 런타임 시간 배열만 확장했다.

## 게임 규칙

- 출구 그림과 `x >= exitX` 클리어 판정을 제거했다. 마지막 안전 발판에 `prologue.clear_gem` ID, `clear_gem` 타입의 보석 1개를 배치했다. 선택 수집품과 별개다.
- 정상 신체 충돌체와 보석 실물 크기의 센서만 사용한다. 후광·모자·머플러는 접촉 판정에 포함하지 않는다.
- 접지 상태와 실제 발 아래 지형을 확인한 뒤 지상 수평 스윕으로 접촉을 검사한다. 착지한 틱에는 공중 궤적을 되감지 않고 착지가 끝난 위치에서만 검사한다. 같은 틱의 낙사·맵 밖 위험 판정을 먼저 처리한다. 현재 프롤로그에 별도 가시·이동 함정은 없으며, 이후에도 위험 판정을 먼저 `resolveGoal`에 전달한다.
- `PLAYING → COLLECTING → CLEARED`. 획득 확정은 한 번만 실행한다. 접촉 틱의 시간을 확정하고 2초 연출 시간은 기록에 더하지 않는다.
- 공중에서 보석에 닿아도 획득·완료 저장·연출을 시작하지 않는다. 접촉을 예약하지 않으므로 다른 곳에 착지했다고 자동 획득되지 않는다. 보석과 닿은 상태로 바닥에 착지하거나 바닥에서 보석에 접근해야 한다.
- 지상 획득이 확정되면 발의 바닥 좌표와 방향을 고정하고 속도·입력 버퍼·줄·갈고리 발사체·총 표시를 제거한다. 물리·후속 위험·카메라 선행 이동도 멈춘다.
- 연출은 별도 시계로 갱신한다. 일시정지와 앱 포커스 상실 시 이 시계도 정지한다. R·발사·갈고리·점프·이동은 획득 중 받지 않으며, 누른 채 진입한 발사/R/Enter는 버튼을 놓은 뒤 새로 눌러야 한다.

## 포즈·레이어

8개 rect와 발 pivot, gem_socket을 그대로 읽는다. 좌우반전은 몸체와 피벗·소켓 X 좌표를 함께 반영한다. 제공 atlas의 기준은 100/100/100/120/120/180/120/160ms다. 런타임에서는 이 순서를 유지하며 200/200/200/240/240/360/240/320ms로 늘린다. atlas 원본은 수정하지 않는다.

발 좌표를 공통 기준으로 두며 전체 획득 시트에는 한 배율만 적용한다. 기존 축소 캐릭터의 모자·부츠 크기에 맞춰 기존 시각 배율 0.75 × 시트 보정 0.84 = 0.63을 사용한다. 프레임마다 크기를 맞추는 재정규화는 하지 않는다. 사용 중인 논리 캔버스/캐릭터 크기와 맞추기 위한 비정수 표시 배율이며, 원본 이미지 리샘플링·프레임 보간은 없다. Nearest 및 정수 논리 위치를 사용한다.

레이어는 후광 → 캐릭터 → 보석 → 링/섬광 → HUD 순서다. 월드 보석은 몸체 높이의 0.4배, 흔들림은 0.02배·1.6초 주기다. 한 보석 렌더 인스턴스만 사용하고 200~600ms에 월드 위치에서 손으로 보간한다. 이후에는 프레임별 소켓을 따른다. 1440~1680ms에는 보석/후광을 숨긴다.

후광은 평소 알파 0.2, 획득 시 0.38이다. 링은 1080ms부터 480ms 동안 0.65→1.8배, 알파 0.4→0으로 재생한다. 섬광은 1080ms부터 280ms만 표시한다. 전체 화면 플래시는 없다.

효과는 각각 독립 텍스처의 **전체 PNG**를 그린다. `visible_bbox_alpha_gt_32`는 실제 크기/중심 계산에만 사용하고 이미지를 잘라내지 않는다. straight-alpha, mipmap off, 캐릭터/보석 Nearest, 후광/링/섬광 Linear를 사용한다.

## 저장·결과 화면

획득 확정 시 `%LOCALAPPDATA%/HookRecoil/completion.json`에 완료 상태·보석 ID·기록·방향·접촉 위치·사망/발사 수·다음 해금 ID `stage_01`을 저장한다. 환경 변수 미제공 시 사용자 홈 아래 `HookRecoil`을 사용한다.

임시 파일 쓰기 → fsync → 재읽기 검증 → 기존 정상 파일 백업 → 원자 교체 순서다. 원자 교체가 지원되지 않으면 기존 파일을 보존하고 저장 실패를 화면에 표시한다. 손상된 본 파일은 정상 백업으로 복구한다. 시도 중에는 완료 확정 한 번만 저장하고 연출 종료 때 다시 저장하지 않는다.

재실행 정책은 **연출을 다시 재생하지 않고 결과 화면으로 복귀**다. 재도전은 Enter/R 또는 결과 화면의 재도전 영역 클릭으로 실행한다. 이전 완료 기록은 보존하므로 재도전 도중 종료해도 이미 달성한 완료가 사라지지 않는다.

현재 콘텐츠는 프롤로그 하나뿐이다. 결과에 `다음 스테이지 · 준비 중`을 표시하며 실제 다음 맵 버튼은 활성화하지 않는다. 존재하지 않는 정식 1스테이지로 이동한 것처럼 처리하지 않는다. 일반 플레이 중 체크포인트 영구 저장은 여전히 미구현이다.

## 구현 파일과 검증

- `collectible/ClearSequence.java`: 상태·연출 시간.
- `collectible/GemSensor.java`: 연속 접촉 판정.
- `assets/GemAssets.java`: 제공 atlas·독립 텍스처.
- `rendering/GemRenderer.java`: 발 고정·손 소켓·빛 효과.
- `save/CompletionStore.java`: 완료 기록 원자 저장·복구.
- `StageRuntime`, `GameplayScreen`: 위험 우선·입력·물리/연출 시계 연결.

검증: `gradlew.bat core:verifyPrologue` 및 `gradlew.bat build`. 세부 결과는 [검증 기록](reports/GEM_CLEAR_VERIFICATION.md)을 따른다. 캡처용 옵션은 `-Dhookrecoil.previewCollection=0.6`, `-Dhookrecoil.previewLeft=true`, `-Dhookrecoil.screenshot=<절대 경로>`다. 캡처 모드는 실제 저장을 읽거나 쓰지 않는다.
