# 지하도시 11~15 구현 및 검증 상태

도시 챕터 원본 가이드와 고정 ID를 유지하면서 `assets/stages/city_01.json`부터 `city_05.json`까지 스테이지 데이터를 구성한다. `tools/BuildCityStages.py`가 반복 생성 부분을 담당하며, 배경·아트는 `assets/city_chapter/`에 있는 기존 리소스를 사용한다. 장치 시뮬레이션은 `CityDeviceRuntime`에 둔다.

## 현재 적용

- 도시 11~15의 카탈로그 항목은 `available=true`로 두어 스테이지 선택과 직접 실행 테스트가 가능하다. 본편 진행 해금 기록과 `available`은 별도 상태다.
- 각 맵에는 수직 발판 경로, 천장 고정점, 스테이지별 이동 발판·기류·장벽·구조물·재충전 링, 중간 체크포인트, 최종 clear gem을 배치했다.
- 천장 빔을 다음 목표 발판의 진행선에서 더 멀리 배치해 발판 위에 걸리거나 도약을 막는 간섭을 줄였다.
- 플랫폼 배치를 다시 조정해 서로 다른 높이의 발판 중심 X가 같은 수직선에 반복되지 않도록 했다. 장벽·기류·재충전 링은 바뀐 동선 쪽으로 이동했다.
- 사다리처럼 보이는 `stairs_right`/`stairs_left`, 사용하지 않는 pillar, 팬 프레임, endpoint_stop, route_arrow를 도시 런타임 아틀라스와 충돌 자료에서 제거했다. 게임에는 플레이어가 사용할 수 있는 사다리 이동 기능이 없다.
- 가시와 붕괴 발판 스프라이트는 실제 장애물 기능에 쓰이므로 유지했다.
- `CityRouteDriver`는 갈고리 입력을 사용하지 않으므로 변경된 지하도시 경로의 통과 가능성 판정에 적합하지 않다. 현재 자동 주행 진단은 11~15 전부 완주를 확인하지 못했으며, 사람 조작을 포함한 경로 검증이 남아 있다.
- 네이티브 검증은 다섯 배경과 도시 아틀라스 로딩, 각 스테이지 로드 및 렌더를 확인한다. 스크린샷은 플레이테스트로 계산하지 않는다.

## 검증 명령

```powershell
.\gradlew.bat :core:verifyCity
.\gradlew.bat :lwjgl3:verifyCityNative
```

`verifyCity`의 정적 데이터·장치 assertion 통과와 자동 주행 진단 결과를 따로 기록한다. FPS별 입력 궤도, 모든 체크포인트의 정지 출발, 실패 후 재시작, 100회 장치 위상 초기화는 아직 검증되지 않았다.
