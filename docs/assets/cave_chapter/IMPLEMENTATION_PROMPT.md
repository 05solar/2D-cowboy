# 개발 에이전트에 전달할 적용 프롬프트

```text
현재 프로젝트를 먼저 조사하고 AGENTS.md, 기존 엔진·언어·화면 전환·입력·저장·자원 로더를 따른다. 새 웹사이트나 다른 엔진으로 교체하지 않는다. 첨부 cave_chapter_assets_v1 묶음을 기존 HOOK & RECOIL 게임에 통합하라.

범위: 프롤로그 다음 동굴 1~5(깨어난 굴, 메아리 협곡, 가시 틈새, 부서지는 발판, 수직 균열)의 시각 리소스와 스테이지 선택 창. 프롤로그는 별도 prologue ID이며 20개 본편 번호에 포함하지 않는다. 완료 조건은 기존 출구 도달 대신 clear_gem 접촉으로 변경한다. 선택 수집품은 별도 ID로 유지한다. 기존 주인공과 gem_pickup_set_v1 획득 연출은 재사용하고 다시 디자인하지 않는다.

assets/backgrounds/의 5개 배경을 stages.json의 ID로 연결한다. 배경은 충돌 없는 한 장짜리 그림이며 seamless 타일이나 실제 맵이 아니다. 배경 바위는 상호작용할 수 없어야 한다. 카메라로 배경을 반복하면 이음새가 생기므로 repeat=false로 사용한다. 5번 세로 배경은 게임 화면비를 세로로 변경하는 용도가 아니라 수직 카메라 배경으로 사용한다. 가장자리가 보이지 않도록 cover·클램프 또는 별도 암부 처리를 하되 플레이 시야는 기존 16:9 규칙을 유지한다.

atlas.json의 실측 rect로 투명 시트를 추출한다. 자동 등분·이미지 크기 기반 충돌 생성은 하지 않는다. terrain은 모듈 지형 조각이며 무이음 자동타일로 가정하지 않는다. 길이가 긴 벽과 바닥은 기존 충돌 타일과 분리된 장식 외피로 배치하고 겹침·이음새는 실제 카메라에서 검증한다. 장식이나 후광이 충돌 판정을 넓히지 않게 한다. 게임플레이 지형은 배경보다 명료하게 보이도록 조정한다.

devices는 고정 링, 연결 상태, 체크포인트 off/on, 바닥·천장·좌·우 가시, 붕괴 발판 intact/warning/collapse/gone을 포함한다. 연결 상태 링에 짧은 로프 그림이 포함돼 있으므로 기존 런타임 줄과 중복 표시되는지 확인하고 필요하면 기본 링에 런타임 상태 색을 적용한다. 붕괴 그림들의 위치가 완벽히 정렬됐다고 가정하지 말고 같은 발판 중심·상단 높이를 기준으로 정렬한다. intact/warning은 원래 발판 충돌 유지, collapse 시작에 충돌 제거, gone은 파편만 남기거나 숨김. 최초 유효 착지부터 약 1초 뒤 붕괴하며 실제 타이밍은 플레이테스트로 조정한다. 경고가 소리와 큰 균열로 먼저 보이게 한다. 재시작 시 상태·타이머를 초기화한다. 가시 충돌은 보이는 날카로운 영역 안쪽으로 잡고 최대 이동 속도에서도 관통하지 않게 한다.

스테이지 구성: 1은 기본 연결·해제·1발 반동과 안전 복구 발판, 2는 높이가 다른 고정점 전환과 이른/늦은 해제, 3은 위·아래 가시 사이 궤도와 제동 착지, 4는 안전한 붕괴 발판 소개 뒤 연속 재출발, 5는 신규 장치 없이 앞선 기술을 결합한다. 중간 체크포인트는 1~4 각 2개, 5는 1개이며 시작점은 별도다. 원 명세의 고정 물리 수치·함정 위상·시야·갈고리 차단 규칙은 임의 변경하지 않는다. 이 묶음은 맵 좌표·검증된 정답 궤도를 포함하지 않으므로 플레이 가능한 맵을 실제로 배치하고 검증하라.

선택 창은 STAGE_SELECT.md와 ui_layout.json, stages.json을 기준으로 구현한다. preview.html은 로컬 레이아웃 참고 화면이며 게임 런타임이 아니다. 텍스트·숫자·기록·잠금 상태를 이미지에 구워 넣지 말고 기존 글꼴 렌더러로 표시한다. 4개 챕터 탭+현재 챕터 스테이지 목록+상세 패널+시작/뒤로 구조를 쓴다. 카드 개수는 데이터 길이로 결정하고 5개를 상수로 박지 않는다. 챕터가 늘어도 화면 전체를 다시 그리지 않는 방식이어야 한다. UI 시트의 plate는 선택 장식으로 재사용하고 모든 가장자리는 nine-slice 또는 엔진의 기본 얇은 패널로 크기에 대응한다. 원본 그림을 비균일 확대해 테두리를 찌그러뜨리지 않는다.

진행 저장과 UI 상태를 분리한다. unlocked는 실제 저장 데이터로 계산하고 available은 해당 빌드에서 구현됐는지 별도 관리한다. 미래 6~20은 이름과 구조만 등록돼 있고 available=false이므로 로드하지 않는다. 기본 모드로 현재 스테이지를 클리어하면 다음 본편이 열린다. 모든 이전 스테이지는 재도전 가능하다. 키보드 포커스와 마우스 선택을 동기화하고 잠긴 스테이지는 자세히 볼 수 있지만 시작은 막는다. no-checkpoint 도전은 해당 스테이지 최초 클리어 후에만 활성화한다. 초점은 색 외에 테두리·표식으로 구분하고 긴 한국어 이름·작은 창·고해상도에서도 글자가 잘리지 않게 한다.

보석 획득 시 COLLECTING 진입, 이동·입력·갈고리·중력·함정 시뮬레이션 정지, 연출 시계는 계속 갱신, 마지막 연출 뒤 CLEARED와 다음 스테이지 해금·저장을 한 번 처리한다. 기록 시간은 접촉 시점에 확정한다. 같은 물리 틱의 사망과 획득은 사망 우선이다. 기존 gem_pickup_set_v1/APPLY.md와 일치시킨다.

완료 전 실제 실행해서 1~5 배경·장치·카드·잠금·해금·재도전·저장 복원·키보드/마우스·리사이즈를 확인하라. 실패→0.7초 이내 재조작 목표, 최대속도 충돌, 30/60/144FPS 궤도 일관성도 해당 변경 범위에서 검사하라. 단순 스크린샷을 플레이테스트 통과로 보고하지 않는다. 변경 파일, 실제 수행한 검증, 미해결 이음새·정렬·진행 불가 항목을 구분해 보고하라.
```
