# 기존 게임에 적용할 프롬프트

```text
기존 HOOK & RECOIL 프로젝트의 AGENTS.md, 엔진·언어·리소스 로더·물리·저장·스테이지 선택 구조를 먼저 읽고 유지하라. 첨부 mine_chapter_assets_v1의 STAGES_06_10.md를 기준으로 광산 6~10을 구현하라. 새 엔진·새 웹사이트로 바꾸지 않는다.

이전 동굴과 다른 어두운 철재·갈색 광산·희미한 황색등 분위기를 사용한다. 다섯 세로 배경은 비반복 원경으로만 배치하고 16:9 플레이 화면과 물리 시야 규칙은 유지한다. 배경의 철골·레일·가시는 실제 콜라이더나 고정점이 아니다. 공통 지형과 장치 시트는 atlas.json rect로 추출하며 자동등분하지 않는다. PNG 알파를 보존한다. 그림 높이로 충돌체를 자동생성하지 않는다. 이 아트는 자동타일이 아니므로 실제 배치 이음새를 검증하라.

STAGES_06_10.md의 상승→하강→재상승 구간과 체크포인트를 실제 맵으로 배치한다. 6~9 각 중간CP2, 10 CP1, 시작점은 별도. 고정 물리 수치·탄약2발·반동·재충전 조건은 유지하고 천장/바닥/벽 가시와 이동체·좁은 착지·제동을 조합해 이전보다 어렵게 한다. 과상승하면 천장 가시, 제동 없는 하강은 바닥 가시에 닿되 정상 궤도는 분명하게 통과해야 한다. 한 픽셀·한 프레임 성공을 강요하지 않는다.

6 승강기·이동링, 7 광차 착지충전, 8 예고 압착기, 9 실제톱·공중 재충전링, 10 종합시험 순서를 유지한다. 공중 재충전링은 9에서 처음 필수 사용한다. 새 배경 효과를 이유로 화상·용암·새 피해체계를 추가하지 않는다.

승강기/광차/이동고정점의 경로·속도·주기·초기위상·ID를 맵데이터에 저장한다. 장치 초기화와 발판 이탈 속도 전달을 일관되게 처리한다. 광차/승강기 위 유효 착지만 충전한다. moving ring 연결로 충전하지 않는다. 톱은 실제 중심/반경과 고정 경로를 가진다. 스프라이트 두 장의 차이만으로 회전 충돌을 계산하지 말고 원형 위험 판정을 사용한다. 압착기는 외형 상태 두 장과 런타임 피스톤 이동을 조합한다. 날카로운 면과 실제 콜라이더를 맞추고 중간 상태에 순간이동시키지 않는다.

이미지 예시 중 광차는 내부가 열린 모양이며 그림의 상단 림과 실제 착지면이 일치하도록 콜라이더를 지정하라. 상판이 더 필요한 경우 기존 플랫폼 그래픽을 별도 합성하고 어디가 착지면인지 분명하게 표시하라. 움직이는 링 카리지 그림과 실제 고정점 중심도 수동 지정한다. 재충전링은 두 발 표시로 일반 링과 구별하고 사용 후 어둡게 하되 시도당1회 규칙을 유지한다.

하강 전에 아래 가시·목표링·안전턱을 카메라가 보여준다. 체크포인트마다 정지·2발 상태에서 통과 가능해야 한다. 시야 밖 기습·랜덤 톱·랜덤 주기·숨은 가시는 넣지 않는다. 가시/줄보정/이동체 충돌은 스윕 또는 CCD로 최대속도에서 검사한다. 사망 후 0.7초 내 재조작 목표를 유지한다.

선택 창에는 stages_patch.json의 mine_01~mine_05만 ID로 병합한다. 기존 cave_01~05와 저장 ID·기록을 덮어쓰지 않는다. artAvailable=true는 아트가 준비됐다는 의미이며 available=false는 맵/물리 검증 전 실행 불가 상태다. 실제 맵을 구현하고 검증한 해당 스테이지만 available=true로 바꿔라. 5 클리어 후6, 6후7 …10후11의 해금을 유지하되 미구현11은 준비중으로 둔다.

완료는 clear_gem 접촉이다. 기존 보석·빛·8포즈 획득 연출을 재사용하고 이동·입력·중력·장치물리 정지와 별도 연출시계를 유지한다. 같은 틱 사망우선, 획득중복방지, 원자저장, CP복원 규칙도 유지한다.

구현 후 실제로 6~10 모두 CP 정지상태에서 클리어하고 과상승/과속낙하 실패와 정상통과를 비교 검증하라. 30/60/144FPS, CP100회 초기화, 이동체 속도·끼임, 위아래 시야, UI잠금/해금, 저장복원도 검사하라. 수행하지 않은 게임테스트는 PASS라고 적지 않는다. 변경파일·실행한검사·미해결항목을 보고하라.
```
