# 동굴 1~5 적용 상태

기준일: 2026-11-09. 이 문서는 cave 에셋과 맵을 현재 libGDX 런타임에 연결한 구현 상태다. 맵 제작 당시 참고 자료는 `docs/assets/cave_chapter/`에 보존한다. 프롤로그는 독립 ID `prologue`; 본편은 `cave_01`~`cave_05`다.

## 데이터·자원

- 시트는 `assets/cave_chapter/atlas.json`의 명시 rect를 `CaveAssets`가 읽는다. 배경은 비반복 장식이며 충돌은 `assets/stages/cave_01.json`~`cave_05.json`에서 따로 정의한다.
- 배치는 `tools/BuildCaveMaps.py`, 자동 경로 데이터는 `assets/stages/cave_routes.json`과 `CaveRouteDriver`가 관리한다. PNG 알파 자동 충돌이나 시트 자동 등분은 하지 않는다.
- 링은 런타임 줄이 포함되지 않은 단일 `anchor_idle`을 사용해 줄 이중 렌더를 막는다.
- 가시는 데이터의 수동 충돌 영역을 사용한다. 장식 크기로 콜라이더를 키우지 않는다.
- 붕괴 발판은 `cave_04`에 3H 4개, `cave_05`에 4H 2개가 있다. `CaveRenderer`는 한 이미지를 발판 전체 너비로 늘이지 않고 최대 2H 폭 조각을 반복해 그린다. 상태 그림은 공통 상단선에 정렬하고 원본 비율을 유지한다. 실제 충돌 해제·복구는 `DeviceRuntime`과 스테이지 데이터가 관리한다.
- `CaveRenderer`에서 합성했던 플랫폼 아래 청회색 면, 상단/천장 하단의 청록 선은 제거했다. 투명 PNG 원본과 충돌 데이터는 유지한다.
- `cave_01`의 첫 천장 갈고리 아래, 주변보다 낮은 x=9~16 복구 발판은 맵과 `BuildCaveMaps.py` 생성 정의에서 제거했다. 해당 틈의 추락 경계는 유지한다.

## 게임 흐름·화면

- 완료는 지상 `clear_gem` 접촉이다. 같은 물리 틱에 사망과 획득이 겹치면 사망이 우선한다. 선택 수집품은 별도 ID다. 세부 규칙과 저장은 [보석 완료](11_GEM_CLEAR.md)를 따른다.
- 붕괴 발판은 첫 유효 착지 뒤 경고를 거쳐 충돌을 제거한다. 재시작/체크포인트 복귀 때 타이머와 상태를 초기화한다. 실제 그림의 시간·위치 정렬은 수동 검증 항목이다.
- 스테이지 선택 창은 카탈로그 기반 탭·목록·상세·시작/뒤로 구조다. 1~15를 테스트용으로 실행 가능하게 두며 진행 잠금과 `available`은 서로 다른 상태다. 잠긴 카드는 상세를 볼 수 있지만 시작은 제한된다.
- 프롤로그만 스테이지명·소개 HUD를 사용한다. 본편 HUD는 시간·탄약·사망·조작 설명을 유지하고 클리어 제목은 `CLEAR`다. 체크포인트 활성화 팝업은 표시하지 않는다.
- 사망 뒤에는 자동 복귀하지 않고 YOU DIED와 조작 키 안내를 유지한다. 재시작은 플레이어 입력으로 한다.
- 기본 데스크톱 창은 1600×900이며 플레이 시야는 16:9다. 창 크기가 커질 때 월드의 표시 배율을 확대하지 않고 더 많은 맵을 보여준다.

## 자동 경로 요약

| ID | 주요 학습 과제 | 최신 기록의 의미 |
|---|---|---|
| `cave_01` | 고정 링, 해제, 안전 착지, 긴 틈 반동 | 자동 입력 경로 있음 |
| `cave_02` | 높이가 다른 링 전환, 해제 시점 | 자동 입력 경로 있음 |
| `cave_03` | 가시 사이 궤도, 제동 착지 | 자동 입력 경로 있음 |
| `cave_04` | 붕괴 발판 도입, 제한 시간 이동 | 자동 입력 경로 있음 |
| `cave_05` | 수직 이동과 링·반동·붕괴 조합 | 자동 입력 경로 있음 |

`:core:verifyCaves`가 30/60/144 FPS의 재현 입력 경로를 검사한다. 이 경로는 정해진 자동 명령의 결정론을 확인하며 신규 플레이어의 난도·가독성 평가 또는 인간 조작 플레이테스트가 아니다.

## 최근 확인 기록

2026-11-09 최신 실행에서 `:core:verifyCaves` 80 assertions, `:lwjgl3:verifyCityNative` 28 checks가 통과했다. 동굴 자동 경로는 30/60/144 FPS에서 동일한 기록으로 완료됐으며, 1스테이지 낮은 발판 제거와 추락 사망 검사가 포함된다. native 검사는 오프닝 카메라 이동을 포함하지만 1280×720 창에서 실행했고, 기본 1600×900의 픽셀 배율·UI 클릭은 아직 확인하지 않았다. cave native 검사의 사망 패널 입력 대기 assertion 실패 이력은 별도로 남아 있어 최신 성공으로 인용하지 않는다.

같은 날 `:lwjgl3:run` 캡처 모드에서 1600×900 cave_01 화면을 확인했다. 플레이어가 서 있는 x=0~8 주 발판이 화면 하단에 온전히 보이고 첫 갈고리 아래 별도 낮은 판은 보이지 않는다. 이 캡처는 시각 확인이며 전체 수동 플레이 검증은 아니다.

카메라 수직 추적 기준을 기존 논리 오프셋 300에서 220으로 낮추고 시작 투어의 스폰/보석 framing도 같은 기준으로 맞췄다. 프롤로그 고정 카메라는 800에서 720으로 내렸다. 도시 네이티브 카메라 회귀는 28 checks 통과했다.

검증을 실행하는 명령:

```powershell
.\gradlew.bat :core:verifyCaves
.\gradlew.bat :lwjgl3:verifyCavesNative
```

## 남은 확인

- 실제 화면에서 발판 조각 접합, 붕괴 상태별 상단 정렬, 경고선과 콜라이더 정렬을 확인한다.
- cave native 사망 패널 대기 검사를 현재 동작과 일치하도록 재현하고 결과를 기록한다.
- 기본 창 1600×900 및 작은/비표준 창에서 UI·마우스 조준·게임 아트 크기·카메라 시야를 확인한다.
- 전 구간을 손으로 플레이하며 난도와 실패 원인 가독성을 평가한다. 캡처만으로 통과를 선언하지 않는다.
