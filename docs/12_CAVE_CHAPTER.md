# 동굴 본편 1~5 통합 명세와 적용 기록

2026-10-28 기준. 기존 Java/libGDX `core`·`lwjgl3` 실행 구조에 `cave_chapter_assets_v1`를 연결했다. 원본 게임 명세와 기존 조작 물리 수치는 수정하지 않는다. 최근 결정인 지상 접촉 보석 획득을 동굴에도 적용한다.

## 프로젝트 파일과 ID

- 제공 묶음의 배경·시트 PNG와 `atlas.json`, `stages.json`, `ui_layout.json`, `validation.json`은 `assets/cave_chapter/`에 원본 그대로 복사했다. 함께 온 적용 문서는 `docs/assets/cave_chapter/`에서 확인한다. `preview.html`은 웹 런타임으로 사용하지 않는다.
- `assets/stages/prologue.json`은 독립 ID `prologue`다. 제공 `stages.json`의 20개 본편에는 `cave_01`~`surface_05`만 들어간다. 광산 이후 15개는 이름과 선행 조건만 보유하고 `available=false`다.
- 동굴 배치: `assets/stages/cave_01.json`~`cave_05.json`. 공통 속성은 `StageDefinition`; 해석은 `StageCatalog` 및 `GameplayScreen.loadStage`가 담당한다. 배경 경로는 카탈로그 ID로 선택하고 `CaveAssets.background`가 필요할 때만 불러온다.
- 실측 좌표의 모든 시트 영역은 `CaveAssets`가 atlas `rect` 그대로 추출한다. 캐릭터 획득 시트는 기존 `GemAssets`가 계속 사용한다. PNG를 수정하거나 자동 등분하지 않는다.
- 맵 좌표 생성기는 `tools/BuildCaveMaps.py`, 재현 가능한 120Hz 실제 입력 경로는 `assets/stages/cave_routes.json`과 `core/src/test/.../CaveRouteDriver.java`에 있다. 맵 콜라이더는 데이터 사각형만 사용하며 배경 그림에서 만들지 않는다.

## 물리·장치 정책

- 각 스테이지에는 시작점, `stages.json`의 수만큼 중간 체크포인트, 하나의 `clear_gem`, 별도 ID의 `optional` 수집품이 있다. 목표 접촉은 기존 신체 충돌체·지상 조건·지지 바닥 검사 및 스윕 센서를 사용한다. 사망이 같은 틱 보석보다 먼저 처리된다.
- 획득 시 시간과 위치를 고정하고 모든 게임플레이 입력을 비운 뒤 갈고리·이동·중력·장치 시뮬레이션을 멈춘다. 요청에 맞춰 두 배 느려진 2초 8포즈 연출 시계만 진행한다. 획득 저널을 즉시 원자 저장하고, 연출이 끝난 뒤 결과·최고 기록·다음 스테이지 해금을 저장한다. 재실행하면 저널을 완료해 결과 화면으로 복귀한다. 획득 애니메이션 자체는 저장된 클리어 시간에 포함하지 않는다.
- 선택 수집품은 ID별 완료 기록에 합쳐 저장하고 클리어 판정에는 쓰지 않는다. 선택 상태·키보드 포커스·스크롤은 진행 파일에 저장하지 않는다.
- `ProgressStore`는 ID 기반 schema v2 진행을 `progress.json`에 기록하고 임시 파일 검증·fsync·원자 교체·백업을 사용한다. 기존 프롤로그 `completion.json`은 새 파일이 없을 때만 `prologue` 완료 기록으로 이관한다. 더 높은 schema를 만나면 읽기/쓰기를 중단해 원본을 덮지 않는다.
- `DeviceRuntime`은 붕괴 발판을 데이터에 명시된 지지면으로만 검사한다. 첫 유효 착지 후 0.45초에 시각 경고·소리를 내고 1초에 충돌을 끄며, 재시작·사망 복귀에서 장치 시간과 충돌을 복구한다. 경고 그림 위치가 불완전하게 정렬된 것을 고려해 발판 중심과 상단에 정렬한다.
- 가시 위험 영역은 배치 JSON의 수동 사각형으로 입력하고, `GemSensor` 스윕으로 빠른 이동의 관통을 막는다. 장식 PNG 크기로 충돌을 생성하지 않는다. 링은 로프가 포함되지 않은 `anchor_idle`만 사용하고 런타임 줄과 겹치지 않는다.
- 모든 물리 초기값은 `assets/config/physics.json`에서 읽는다. 중력·이동·사거리·발사 속도·반동은 유지하며 사용자 조정으로 갈고리 링의 적중 허용 반경을 0.28H로 넓혔다.
- 수직 균열도 1280×720 플레이 뷰포트를 유지한다. 배경은 `repeat=false`, 화면 비율을 채우는 cover와 clamp 방식으로 그리고, 카메라만 세로로 따라간다.

## 스테이지 선택

`StageSelectView`는 기존 `InputProcessor`를 모달 동안 교체해 게임 입력과 클릭 관통을 차단한다. 4개 탭과 카탈로그에서 생성한 현재 스테이지 카드, 기록 상세, 시작·뒤로·프롤로그를 표시한다. 스테이지 목표 설명과 공통 보석 안내 문구는 표시하지 않는다. 글자는 기존 비트맵 글꼴, 테두리와 패널은 얇은 기본 패널이다. 1280×720 이상에서는 좌우 패널, 작은 창에서는 목록과 상세를 세로로 쌓고 목록 행을 스크롤한다. 카드 선택과 키보드 포커스를 별도로 표시하고 방향키/W·S, Tab, Enter, Escape를 처리한다.

플레이 HUD는 프롤로그에서만 기존 스테이지명·구역 제목·소개 문구·구역 진행 막대를 보여준다. 동굴 본편에서는 이를 숨기고 조작 키 안내, 경과 시간, 탄약, 사망 수, 체크포인트 표시는 유지한다.

카드 해금은 선행 ID의 저장 완료 기록으로 계산한다. `available`이 false면 선행을 완료했어도 시작할 수 없다. 클리어한 본편은 재도전할 수 있고, 노체크포인트 도전은 해당 스테이지를 기본 모드로 클리어한 뒤 연다. M으로 모달을 열고 Esc로 닫는다. N은 클리어 후 다음 해금 스테이지를 연다.

## 맵 과제와 현 검증 경로

| ID | 구현 과제 | 검증 입력 경로 (시작부터 보석) |
|---|---|---|
| cave_01 | 안전 복구 지면, 고정 링 연결·해제, 링이 없는 구멍의 반동 | 링 구간과 반동 구간 2회 |
| cave_02 | 높이가 다른 링 전환, 이른/늦은 방향 해제 | 고저차 링 2개와 반동 |
| cave_03 | 네 방향 가시 배치, 스윙 후 제동 착지 | 링·반동·브레이크·짧은 점프 |

현재 맵은 실제 시작 위치에서 플레이어 입력으로 클리어했다. 이것은 경로를 재현하는 자동 플레이테스트 결과이며 사람의 손 조작 평가를 뜻하지 않는다. 제공된 아트는 모듈형이며 접합부가 자동 타일로 검증되지 않았으므로 새 지형 패턴을 추가할 때마다 엔진 뷰에서 접합과 카메라 위치를 확인한다.

## HUD·보석 가독성 조정 (2026-10-28)
하단 조작 안내를 키 이름과 설명의 별도 크기로 렌더한다. A/D·SPACE 같은 입력 설명은 기존보다 키우고, M/R/ESC/F1 표기는 한 단계 더 크게 표시한다. 스테이지 카드·상세 패널 글자에 여백을 추가했다. clear_gem은 캐릭터 높이 기준 0.52배, 선택 보석은 0.468배의 표시 높이를 쓰며 기존 보석 PNG 주변에 청록 후광을 부드럽게 맥동시킨다. 렌더 크기와 광원은 충돌 센서에 영향을 주지 않는다.

검증: :lwjgl3:verifyCavesNative 31 checks PASS 및 :lwjgl3:jar 성공. 1280×720/640×480 선택 화면 레이아웃, HUD 키 글자 위계, 동굴 1 시작 화면의 확대 보석과 후광을 실제 실행 캡처로 확인했다.


동굴 4 추락 처리 보정: 붕괴 발판 아래 받침을 제거했다. 붕괴 뒤 y=1 낙하 경계에서 사망하므로 발판 아래로 떨어지면 체크포인트로 복귀한다. 사망 HUD는 YOU DIED와 R 재시작/M 스테이지 선택/ESC 일시정지 설명만 표시한다. 일시정지 안내에서 숨 고르기 문구와 착지·계획 안내를 지웠다. 최신 검증은 cave 73 assertions, prologue 131 assertions, native 32 checks 통과 및 JAR 빌드 성공.
