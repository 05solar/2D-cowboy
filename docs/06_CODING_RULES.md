# 코드 작성 규칙

이 문서는 앞으로 추가·수정하는 프로젝트 소스에 적용한다. 관련 기능 구현과 함께 기존 파일도 규칙에 맞춘다.

## 기능별 파일 분리 — 필수

- Java 최상위 주요 클래스는 파일 하나당 하나, 파일명은 클래스명과 일치시킨다.
- 입력, 이동, 갈고리, 반동, 충돌, 함정, 체크포인트, 저장, UI, 렌더, 음향은 [구조 문서](04_PROJECT_STRUCTURE.md)의 각 패키지로 분리한다.
- 한 파일에 서로 다른 기능을 추가하지 않는다. `Main`/`Game`/`Screen`은 조립·호출·화면 수명만 담당한다.
- 데이터 클래스와 동작 시스템, 게임 판정과 화면 표시, 플랫폼 I/O와 게임 규칙을 구분한다.
- 여러 이유로 수정되는 파일은 책임을 나눈다. 300줄을 넘으면 분리 필요성을 검토하되 줄 수를 맞추기 위한 기계적 분할은 하지 않는다(검토 기준).
- 의미 없는 `Utils`, 거대한 `Manager`, 순환 import, 공유 mutable static 상태를 피한다. 공통 코드는 실제 중복과 책임이 확인될 때 추출한다.

## 모든 직접 작성 코드 파일의 상단 설명 — 필수

파일을 열자마자 무엇을 담당하는지 알 수 있도록 첫 설명 블록에 **파일명, 역할, 주요 책임, 협력 대상, 관련 사양**을 한국어로 적는다. 상태를 소유하는 파일은 초기화·해제 책임도 적는다. 설명은 현재 코드와 함께 갱신한다.

Java는 `package` 이전에 아래 형식을 사용한다. 라이선스가 있으면 라이선스를 먼저 보존하고 그 아래에 작성한다.

```java
/*
 * 파일: GrappleSystem.java
 * 역할: 갈고리 발사, 고정점 적중, 연결 및 해제 흐름을 관리한다.
 * 주요 책임: 사거리/재발사 간격 검사, 줄 차단 검사, 연결 상태 전환.
 * 협력 대상: InputFrame, CollisionQuery, RopeConstraint, PlayerState.
 * 수명: 스테이지가 소유하며 재시작 시 비행체와 연결 상태를 초기화한다.
 * 관련 사양: docs/03_FEATURE_SPEC.md (갈고리), 원본 5.2절.
 */
package io.github.hookrecoil.grapple;
```

테스트 파일에는 검증 대상과 실패를 막는 규칙을 설명한다. Gradle/Groovy는 `/* ... */` 또는 `//`, PowerShell은 `<# ... #>`, Python은 첫 모듈 설명 문자열 등 해당 언어가 허용하는 형식을 사용한다. shebang/인코딩 지시문은 필요한 첫 줄을 유지한다.

JSON·이미지·오디오처럼 주석을 지원하지 않는 형식에는 주석을 억지로 넣지 않는다. 같은 이름의 `.md` 설명 파일 또는 폴더 `README.md`에 파일별 역할을 대응시킨다. 생성된 에셋 목록·Gradle wrapper·외부 라이브러리·자동 생성 코드의 헤더를 임의 수정하지 않는다. 직접 수정한 외부 기반 파일은 원 저작권·라이선스를 보존한다.

## 코드·수치·명명

- UTF-8, LF, Java 들여쓰기 4칸, Gradle 2칸. 기존 `.editorconfig`를 따른다.
- 패키지 소문자, 클래스 `PascalCase`, 변수·함수 `camelCase`, 상수 `UPPER_SNAKE_CASE`.
- 단위 혼동을 막도록 `cooldownSeconds`, `speedHPerSecond`처럼 명명한다. 픽셀값을 물리 값에 섞지 않는다.
- 게임 수치는 중앙 설정에서 읽고 검증한다. 여러 코드에 `5.5`, `7`, `0.22` 등을 흩어 쓰지 않는다.
- 현재 Java 8 호환 범위에서 구현한다. 언어 수준 변경은 빌드·실행·배포 영향까지 기록한다.
- 주석은 코드의 단순 번역보다 제약·이유·경계 상황을 설명한다. TODO에는 해결 조건과 관련 작업을 남긴다.

## 상태·리소스·오류

- 입력은 이벤트→틱 명령으로 바꾸고 렌더 메서드에서 게임 상태를 갱신하지 않는다.
- 시스템 간 의존성은 생성자/명시적 계약으로 전달한다. UI가 탄약·저장 파일·플레이어 위치를 직접 변경하지 않는다.
- 텍스처·배치·사운드 등은 생성/로드한 소유자가 한 번만 해제한다. 공유 에셋을 개별 화면이 임의 해제하지 않는다.
- 재시작 가능한 장치는 기준 초기화 계약을 갖춘다. 생성자 초기화와 체크포인트 리셋이 다른 결과를 만들지 않게 검증한다.
- 핫 루프의 불필요한 객체 생성·파일 접근·로그 출력을 줄인다. 저장은 물리 판정 중간이 아니라 상태 확정 뒤 요청한다.
- 오류를 삼키지 않는다. 맵 ID·오브젝트 ID·파일 위치를 포함하되 개인 경로·환경 변수 등 민감 정보를 불필요하게 출력하지 않는다.
