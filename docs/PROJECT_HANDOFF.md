# 프로젝트 인수인계

기준일: 2026-11-09. 새 작업자는 루트 [AGENTS.md](../AGENTS.md), 이 문서, [문서 색인](README.md), [현재 상태](09_DECISIONS_AND_STATUS.md)를 먼저 읽고 코드·데이터로 상태를 확인한다. 이 문서는 원본 사양이나 런타임의 대체물이 아니다.

## 프로젝트와 실행

- 기존 Java/libGDX 프로젝트: `core` 게임 로직, `lwjgl3` 데스크톱 런처. Gradle wrapper는 저장소 루트에 둔다.
- 게임 실행: 프로젝트 루트 PowerShell에서 `.\gradlew.bat :lwjgl3:run`.
- 데스크톱 JAR: `.\gradlew.bat :lwjgl3:jar`.
- 기본 창 크기: 1600×900. 월드 렌더 배율은 창 크기 변화로 커지지 않으며, 창이 커질수록 월드 시야가 넓어진다. 게임 플레이 영역은 16:9다.
- 프롤로그 ID `prologue`; 본편 고정 ID는 `cave_01`~`city_05`(1~15), `surface_01`~`surface_05`(16~20). 본편 1~15는 테스트 실행 가능 설정, 16~20은 실행 맵 부재로 `available=false`다.

## 현재 구현 요약

- 물리 시뮬레이션은 고정 120Hz다. 조작·맵·물리 설정은 기능별 코드/JSON에 둔다.
- 기본 조작은 A/D 이동, Space 점프, 마우스 조준, 왼쪽 클릭 반동 사격, 오른쪽 버튼 갈고리, R 체크포인트 재시작, Esc 일시정지, M 스테이지 선택이다.
- 갈고리는 유효한 고정점에 연결한다. 반동 탄창은 2발이며 정상 착지와 스테이지별 충전 링으로 회복한다. 개별 스테이지와 장치 경로의 완주 가능성이 모두 검증된 것은 아니다.
- 완료 목표는 바닥의 `clear_gem`이다. 획득 확정 시 기록 시간을 멈추고 입력·물리·장치를 정지한 뒤 별도 시계로 2초 애니메이션을 재생한다. 결과 화면 제목은 `CLEAR`다.
- 사망 화면은 자동 재시작하지 않고 YOU DIED 패널에서 입력을 기다린다. 체크포인트 알림 팝업은 표시하지 않는다.
- 게임 카메라의 수직 look offset은 220 논리 픽셀로 낮췄고, 프롤로그 고정 카메라는 y=720이다. 동굴 1의 첫 갈고리 아래 x=9~16 낮은 복구 발판을 제거했다.
- 신규 스테이지 시작 시 스폰→전체 맵 축소 보기→클리어 보석 확대 보기→스폰 복귀 카메라 투어를 한다. 게임 시뮬레이션은 연출 중 정지한다.
- 붕괴 발판은 동굴 4·5에서만 쓰인다. 긴 이미지를 한 장으로 늘이지 않고 최대 2H 조각으로 반복 렌더한다. 충돌은 스테이지 데이터/런타임 상태가 소유한다.
- 동굴 1~5, 광산 6~10, 지하도시 V2 11~15의 시각 자료와 실행 데이터가 있다. 개발 맵이 있다는 사실은 수동 난도·클리어 검증을 뜻하지 않는다.

## 현재 작업 트리 주의

인수인계 작성 시점에 최근 게임 변경과 관련 문서 편집이 커밋되지 않은 상태로 남아 있다. 다른 작업을 시작하기 전에 `git status --short`와 `git diff`를 확인하고, 이미 존재하는 변경을 덮어쓰거나 실수로 포함하지 않는다. 이 문서 갱신은 커밋·푸시를 뜻하지 않는다.

최근 미커밋 변경 묶음에는 카메라/기본 창 뷰포트, CLEAR 및 체크포인트 안내, 보석 크기, 동굴 에셋 오버레이와 붕괴 발판 렌더링, 관련 검증 코드·문서가 포함된다. 정확한 목록은 실행 시점의 Git 상태가 기준이다.

## 최근 실행한 검증과 한계

2026-11-09 문서 정리 전 코드 작업에서 확인한 결과:

- `:core:verifyCaves`: 80 assertions 통과. 동굴 경로는 30/60/144 FPS 자동 검증을 포함한다. 인간 조작 플레이테스트나 다른 챕터의 통과를 의미하지 않는다.
- `:lwjgl3:compileJava`: 통과.
- `:lwjgl3:verifyCityNative`: 28 checks 통과. 도시 V2 자료와 맵 로드, 오프닝 카메라 연속성·정지 동작을 확인했다. 수직 look offset 수정 후 재실행했다. 검증 창은 1280×720이며 1600×900 실제 창의 픽셀 배율은 별도 확인하지 않았다.
- 1600×900 `:lwjgl3:run` 미리보기 캡처에서 cave_01 시작 발판이 하단에서 잘리지 않는 것을 확인했다. 정지 화면 검사이며 플레이 경로 검증이 아니다.
- `git diff --check`: 통과. 줄바꿈 형식 경고가 출력될 수 있으나 공백 오류는 없었다.
- 이전 기록의 `:core:verifyMines`는 mine_01 자동 드라이버가 갈고리를 쓰지 않아 중간 위치에서 실패했다. 이 결과는 수동 플레이의 성공/실패를 대신하지 않는다.
- 이전 cave native 검증 기록에는 사망 패널 입력 대기 assertion 실패가 있다. 이후 테스트 코드/화면 작업이 있었으므로 재실행 전에는 최신 상태로 단정하지 않는다.

전체 수동 클리어, 모든 체크포인트의 정지 출발, 100회 장치 위상 재시작, 최대속도 충돌, 30/60/144 FPS 전체 챕터 비교, 난이도 상승, 1080p 성능·배포 패키지는 완료로 기록하지 않는다.

## 다음 작업 재개 순서

1. `git status --short`로 미커밋 변경을 보존하고 이번 요청과 무관한 파일을 건드리지 않는다.
2. 요청과 관련한 원본 사양·맵 데이터·렌더링/물리 구현을 확인한다. 문서 계획을 구현 완료로 오인하지 않는다.
3. 기능 변경 뒤에는 관련 검증을 실행하고 명령·결과·한계를 이 인수인계와 상태 문서에 기록한다.
4. 맵을 바꿀 때 생성기/JSON, `available`, 진행 저장 ID와 해당 챕터 상태 문서를 함께 대조한다.
5. 사용자가 명시하지 않은 커밋·푸시는 하지 않는다.
