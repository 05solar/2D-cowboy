# 개발 프로세스

기준: [원본](specs/HOOK_RECOIL_Game_Spec_v1.md) 15~17절. 날짜 약속 대신 단계별 통과 조건으로 관리한다.

## 단계별 진행

| 단계 | 작업 및 산출물 | 다음 단계 진입 조건 |
|---|---|---|
| P0 기반 준비 | 기존 템플릿 실행 확인, Java/Gradle 환경 기록, 패키지명 전환, 입력·고정 시간 루프·도형 테스트맵 | 데스크톱 실행·종료·리사이즈 정상, 120Hz 루프 확인 |
| P1 조작 실험 | 이동·점프·갈고리·반동·재연결, 정적 충돌, 디버그 시각화, 입력 재생 자료, 물리 구현 결정 | 30/60/144FPS 궤도 기준 통과, 관통·무한 충전 없음, 두 도구의 결합이 유용함 |
| P2 대표 맵 | 1·3·5번 회색 도형 초안, 사망·체크포인트·빠른 재시작, 카메라 | 학습·제동·연속 기술이 각각 성립, 0.7초 내 조작 복귀 목표 충족 |
| P3 공통 시스템 | 데이터 로더·검증기, 메뉴·설정, 저장·복구, 해금·기록, 수집 저장 계약 | 저장 후 재실행과 맵 전환 정상, 손상 파일 복구, 재시작 100회 일관 |
| P4 동굴 완성 | 1~5 전체, 붕괴 발판, 첫 테마 아트·음향·안내 | 새 플레이어가 기본 규칙 학습, 5번은 기존 기술만 종합, 맵별 모든 체크포인트 통과 |
| P5 테마 확장 | 광산 6~10 → 지하도시 11~15 → 지상 16~20 | 새 장치를 실험맵에서 검증한 후 맵 제작, 20개 순차 진행 가능 |
| P6 출시 필수 완성 | 20개 수집품, 시작·테마 전환·엔딩, UI·음향·설정·가독성·밸런스 | 검증 계획의 필수 항목 통과, 기준 PC 측정, 깨끗한 환경에서 배포본 실행 |
| P7 후순위 도전 | 노체크포인트, 구간 연습, 목표 시간 표식, 별도 기록 도전 UI | 일반 모드 20개 검증 완료 후 진행, 기록 분리·연습 기록 제외 확인 |

P1에서 조작을 안정시키기 전에 20개 맵을 양산하지 않는다. 단색 도형으로 검증한 뒤 아트를 제작한다. 단계 실패 시 해당 원인을 해결하고 영향받는 맵만 재검증한다.

## 첫 구현 작업 순서

1. `gradlew.bat --version`과 템플릿 실행 결과를 기록한다.
2. `io.github.some_example_name`을 계획된 패키지로 옮기며 Gradle 실행 클래스·런처 import도 함께 수정한다.
3. `HookRecoilGame`, `GameplayScreen`, `FixedStepLoop`, `InputRouter`, `InputFrame`을 만든다.
4. H 단위 테스트맵, 플레이어 충돌체, 이동·점프·착지 판정을 만든다.
5. 반동·탄약, 고정 갈고리·줄 제약·차단, 둘의 조합을 순서대로 붙인다.
6. 고속 충돌과 이동 고정점 실험으로 물리 방식의 채택 여부를 결정한다.
7. 사망·복원·카메라를 붙여 1·3·5번 초안을 만든다.

## 기능 하나를 완료하는 절차

1. 관련 사양·원본 절 번호·완료 조건을 작업에 적는다.
2. 데이터와 런타임 상태, 책임질 파일, 기존 기능과의 경계를 정한다.
3. 기능별 파일에 구현하고 상단 설명 주석을 작성한다.
4. 수치와 맵 배치를 데이터로 분리한다. 실험맵에서 먼저 확인한다.
5. 의미 있는 자동 검증과 수동 플레이를 수행한다. 검증하지 못한 항목은 명시한다.
6. 기능·데이터 형식·파일 위치가 바뀌면 문서도 수정한다.
7. 변경 내용·검증 결과·남은 문제를 기록한 뒤 다음 작업으로 이동한다.
