# 검증 계획

현재 아래 검증은 **실행 전 계획**이다. 구현 이후 결과를 `docs/reports/`에 기록한다. 원본 16절의 합격 기준을 우선한다.

## 필수 검증표

| ID / 관련 기능 | 검증 방법 | 합격 조건 | 시점 |
|---|---|---|---|
| T01 물리 | 동일 tick별 입력·조준 월드 좌표를 30/60/144FPS에서 재생 | 경로·생존 결과 동일, 주요 도착점 차이 ≤0.05H 목표 | P1 |
| T02 점프 | 코요테·입력 버퍼 경계 전후, 벽 접촉 | 0.08/0.10초 규칙, 이단·벽 점프 없음 | P1 |
| T03 줄 | 느슨함·팽팽함·해제·반동·이동 고정점 | 거리 제약, 접선 보존, 자동 끌어올림/속도 중복 없음 | P1 |
| T04 충돌 | 16H/s에서 얇은 벽·바닥·위험물 및 줄 위치 보정 | 관통 없음, 일반 벽은 사망 아님 | P1 |
| T05 자원 | 0/1/2발, 발사 간격, 벽 스침, 링 반복 통과, 착지 후 즉시 발사 | 무한 충전 없음, 2발 상한, 링 1회, 간격 준수 | P1 |
| T06 복원 | 각 체크포인트에서 100회 재시작·동일 입력 | 위치·속도·줄·탄약·링·장치 위상 일관 | P2/P3 |
| T07 우선순위 | 같은 틱 사망+출구/체크포인트/수집 | 사망 우선, 잘못된 해금·저장 없음 | P2/P3 |
| T08 입력 | 유지 클릭 중 사망, 토글, 리바인딩, 포커스 상실·복귀 | 복귀 자동 발사 없음, 짧은 클릭 유실/중복 없음 | P1/P3 |
| T09 시간 | 사망 대기·R·일시정지·포커스·새 시도 | 사망 대기는 포함, 비활성은 제외, CP에서 기록 유지 | P3 |
| T10 저장 | 저장→종료→재실행, 쓰기/교체 중 실패, 본 파일 손상 | 정상 백업 복구, 진행·설정 복원, 미래 버전 덮어쓰기 없음 | P3 |
| T11 수집 | 획득→사망/CP/출구, 재방문 | 임시 취소·영구 확정 구분, 해금 비필수 | P3/P6 |
| T12 이동체 | 광차·이동 링에서 점프·해제·발사, 끼임 | 속도 전달 1회, 관통 없음 | P5 전 |
| T13 맵 | 20개 모든 시작/CP에서 속도 0·2발로 출발 | 모든 기본 경로 완주, 시야 밖 필수 링 없음 | P4~P6 |
| T14 화면 | 창 크기·16:9·울트라와이드·여백 클릭 | 조준 일치, 동일 월드 시야, 가독성 확보 | P2/P6 |
| T15 재시작 | 사망 판정부터 제어 가능까지 계측 | 연출 ≤0.25초, 입력 가능 ≤0.7초 목표 | P2/P6 |
| T16 성능·배포 | 기준 PC 1080p, 최다 장치 구간·반복 재시작, 새 환경 배포본 | 60FPS 이상 목표, 지속 메모리 증가 없음, 실행·저장 정상 | P6 |
| T17 후순위 모드 | 노체크포인트·연습·기록 도전 | 시작 복원, 모드별 분리, 연습 기록 제외 | P7 |

자동 검증 대상은 순수 수학·시간·탄약·직렬화·상태 전이·데이터 유효성이다. 실제 충돌/렌더/입력은 통합 실험맵으로 확인하고 재미·시야·난이도는 사람이 플레이한다. 자동화 도구 선택과 테스트 의존성 추가는 P0/P1에서 수행한다.

## 입력 재생 기록

빌드/규칙 버전, 스테이지/체크포인트, tick 번호, 행동 press/release/hold, 조준 월드 좌표, 초기 장치 위상을 기록한다. 결과에는 주요 위치·속도·탄약·사망 원인·출구 도달 틱을 남긴다. 렌더 FPS 차이가 입력 샘플링 차이로 바뀌지 않게 동일 틱 명령을 사용한다.

## 플레이테스트

신규 플레이어와 액션 경험자를 구분해 1·3·5부터 관찰한다. 기록 항목: 구간, 시도 수, 성공 시간, 사망 원인(조준/해제/과속/탄약/위상/시야/충돌), 다음 시도 전략 변화. 작은 표본을 전체 사용자 통계로 주장하지 않는다.

막히는 이유를 설명하지 못하면 난이도를 높이기 전에 안내·시야·충돌을 수정한다. 순수 주행 시간과 실패 포함 첫 클리어 시간을 구분한다. 목표 시간 표식은 실제 기록 분포 이후 결정한다.

## 보고서 양식

```text
날짜 / 빌드 / rulesVersion:
환경(OS, CPU, GPU, RAM, 해상도, 입력 장치):
검증 ID / 맵·체크포인트:
초기 조건 / 재현 입력:
기대 결과 / 실제 결과 / 측정값:
판정(PASS / FAIL / NOT RUN):
증거 파일 / 결함 / 수정 후 재검증:
```

릴리스는 모든 필수 항목을 통과한 빌드와 데이터 버전을 고정한 뒤 패키징한다. 기능이 없는 상태의 빌드 성공을 게임 완성 검증으로 대체하지 않는다.
