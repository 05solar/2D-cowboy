# 데이터·저장 사양

원본 9, 11~13절을 구현하기 위한 **설계안**이다. 실행용 데이터는 JSON을 기본으로 하고 타일 편집 포맷은 별도 결정한다. 파서·검증기는 아직 없다.

## 공통 데이터 규칙

- UTF-8, 시간은 초, 좌표·길이는 H, 가속은 H/s², 각도 단위는 필드명으로 구분한다.
- 스테이지 ID는 `stage_01`~`stage_20`, 오브젝트 ID는 `stage_01.anchor_01`처럼 전역 충돌 없이 부여한다. 저장에 쓰인 ID는 재배치해도 유지한다.
- 정의 데이터와 런타임 상태를 분리한다. JSON의 초기값을 실행 중 직접 변경하지 않는다.
- `schemaVersion`은 형식, `rulesVersion`은 물리/맵 규칙의 기록 호환 버전이다.
- 필수 필드 누락·중복 ID·해결 불가능한 참조·NaN/무한 값·음수 크기는 오류다. 개발 중에는 위치와 ID를 보고하고 해당 맵 진입을 막는다.

## 스테이지 정의

| 필드 | 형식·검증 |
|---|---|
| schemaVersion, rulesVersion | 지원하는 버전 |
| id, theme, nameKey, order | 고유 ID, cave/mine/city/surface, 표시 문자열, 1~20 |
| bounds | x/y/width/height, 폭·높이 양수 |
| spawn, exit | 시작 위치, 출구 사각형, 안전성 수동 검증 |
| terrain | 타일맵 참조 또는 충돌 형상 목록, 충돌 마스크 |
| checkpoints | ID, 안전 스폰, resetProfileId. 시작 체크포인트도 명시 |
| resetProfiles | 체크포인트별 장치 초기 위상·활성·복원 상태 |
| anchors | ID, 위치, 적중 반경, 선택 motionPathId |
| motionPaths | ID, 경유점, 왕복/루프, 주기, 초기 위상 |
| platforms | ID, 형상, 종류, 선택 경로, 붕괴 지연 |
| hazards | ID, 타입, 위험 형상, 주기·예고 시간·위상·차단 마스크 |
| windZones | ID, 영역, accelerationX/Y |
| rechargeRings | ID, 중심, 반경 |
| collectibles | ID, 위치, 스테이지당 1개 |
| cameraZones | ID, 영역, 경계·선행/데드존 프리셋 |
| routeMetadata | 구간·학습 기술·관찰 지점, 검증 자료 참조 |

배열은 해당 요소가 없을 때 빈 배열로 표시한다. 고정점 사거리와 반동량 같은 공통 수치는 맵마다 복제하지 않는다. `assets/config/physics.json`의 단일 튜닝값을 사용한다. 맵 좌표·기류·장치 시간은 스테이지 데이터가 소유한다.

검증기는 중간 체크포인트 수(5·10·15번은 1개, 나머지는 2개), 수집품 1개, 최소 3구간, 참조 경로 존재와 기본 필드 범위를 검사한다. 실제 도달 가능성·시야·위험 가독성은 플레이 검증을 별도로 수행한다.

## 체크포인트 복원

복원 단위는 `CheckpointSnapshot`이다. 안전 스폰, 장치별 초기 위상, 붕괴 상태, 링 사용 초기 상태를 정의한다. 생존 도달 시 현재 체크포인트와 임시 수집품을 확정 저장한다. 도달 당시 공중 속도나 함정의 우연한 위상을 저장하지 않는다.

복원 순서: 입력 차단·버퍼 삭제 → 이전 줄/투사체/효과 정리 → 장치·링 기준 복원 → 위치·속도 0·탄약 2·접촉/쿨다운 초기화 → 카메라 재배치 → 새 입력 허용. 도중에 업데이트나 저장이 끼어들지 않게 한다. 타이머·사망 수는 `RunTracker`에 남긴다.

## 저장 스키마

| 필드 | 내용 |
|---|---|
| schemaVersion, rulesVersion | 저장 형식·기록 규칙 버전 |
| progression | 최고 해금 번호, 클리어 스테이지 ID |
| resume | stageId, checkpointId, mode, elapsedSeconds, deathCount |
| collectibles | 영구 확보 ID 목록 |
| records | stageId + mode + rulesVersion별 bestTime, minimumDeaths, 완주 표식 |
| settings | 행동별 키, 음량, 화면 모드, 흔들림, 섬광 감소, 갈고리 방식 |

임시 수집품·현재 속도·공중 위치·활성 줄은 저장하지 않는다. 기존 기록과 호환되지 않는 물리/맵 변경은 rulesVersion을 올리고 이전 기록을 보존·구분한다. 새 게임은 진행 초기화이며 설정 보존 여부와 UI 확인은 P3에서 정한다.

## 파일 안전성

Windows 저장 위치 설계안: `%LOCALAPPDATA%/HookRecoil/`. `save.json`, `save.tmp`, `save.backup.json`을 같은 디렉터리에 둔다. 플랫폼 경로 선택은 `DesktopSaveStorage`가 책임진다.

1. 저장 요청을 직렬화한다. 설정 변경·체크포인트·수집 확정·클리어가 트리거다.
2. 메모리 스냅샷을 직렬화하고 스키마/참조를 검증한다.
3. 임시 파일에 기록·flush·닫기 후 다시 읽어 검증한다.
4. 기존 본 파일이 정상일 때만 정상 백업을 갱신한다. 손상된 본 파일로 백업을 덮지 않는다.
5. 같은 파일시스템의 안전한 교체 연산으로 본 파일을 교체한다. 원자 교체 미지원 환경의 실패 복구는 별도로 검증한다.
6. 실패 시 현재 플레이는 유지하고 저장 실패와 재시도 수단을 표시한다. 정상 백업을 보존한다.

시작 시 본 파일 → 정상 백업 순으로 검증한다. 둘 다 손상되면 원본을 보존하고 복구 안내 후 새 진행을 제공한다. 알 수 없는 미래 schemaVersion은 자동 초기화·덮어쓰기하지 않는다. 지원하는 구버전만 `SaveMigrator`로 변환하고 변환 전 백업을 남긴다.

이어하기의 시간·사망 수는 마지막 성공 저장 시점 기준이다. 정상 종료/타이틀 이동에서도 안전한 현재 체크포인트 정보와 누적 기록을 저장하도록 설계한다. 강제 종료의 미저장 경과 시간까지 보장하지 않는다.
